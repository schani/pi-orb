1. **History publication failure escaped the adapter.** Injecting an SDK `getEntries()` failure during final child release threw instead of returning a typed publication error. After catching it, a duplicate terminal could still finish successfully once reads recovered. `flushPersisted()` now maps source exceptions to `history_source_error`, and aggregate finalization requires ready health. Failure stays visible and activity conservative. `activity-before.log` / `activity-after.log` retain the unit regression, not a DST trace.
2. **Archive watchdog excluded the mandatory quarantine.** The extended browser scenario reached archive correctly but its 60-second watchdog was shorter than the existing 65-second deletion quarantine. Its budget now explicitly includes `DEFAULT_LIFECYCLE_CONSTANTS.deletionQuarantineMs`; named FIFO gates still establish all execution ordering. The corrected scenario passed (~220 s). This is a lifecycle-budget assumption correction, not a timeout increase concealing stalled progress.
3. **Shutdown returned before child tool cleanup.** The installed-SDK trace in `shutdown-before.log` shows `tool:one:abort-observed`, then `shutdown:returned`, while the cleanup gate is closed. Upstream disposal awaits extension hooks, not the execution promise. The host now registers its cancellation/drain handler before upstream teardown, retaining public terminal observers until its owned runs drain. `shutdown-after.log` shows tool exit and durable terminal before teardown returns. One explicit event-loop boundary drains the scripted hooks' microtasks; there is no timed grace period or private manager-promise read.
4. **Start edges were missing.** The bridge treated `started` as redundant admission and discarded it. The `start-edge-before.log` regression requires the durable start record; the bridge now records it for an already-owned run. Installed-SDK scenarios enforce this edge.
5. **Luna omitted delegated outcomes.** Generic root events were filtered out of summary input. The real-SDK regression in `summary-before-corrected.log` demonstrates the missing outcome despite correct aggregate scheduling. The Pi adapter now creates a summary-only status/description projection, without raw child/tool output. The same contract requires one summary after aggregate drain containing the child outcome and root follow-up. `summary-before.log` preserves an earlier fixture typo (undefined operation-ID variable), corrected before the meaningful reproduction; it is not product-failure evidence.
6. **Docker upload assertion sampled the two-frame handoff.** The first full Docker/PostgreSQL run passed 84 tests and failed the existing upload visibility assertion: both the live and persisted `UPLOAD_VERIFIED` paragraphs were present between history publication and `output_retired`. It explicitly fails if two persisted replies exist; no `.first()` or weakened visibility assertion is used. Only the diagnostic excerpt is exported: raw mock headers stay in the ignored local log. The repaired full-slice file passed all four cases. Fetching current `main` then revealed its existing product-level atomic output-handoff repair; that repair is now merged too, so the branch does not retain the two-frame product behavior.
