# Native MCP transport exploration

Isolated Node 24 / Pi coding-agent, pi-ai and pi-mcp 0.99.1; neverthrow 8.2.0 and tsx 4.23.15. Install with `npm ci --prefix scripts/native-mcp-exploration --ignore-scripts`; run `npm test --prefix scripts/native-mcp-exploration` (Node's `--experimental-import-meta-resolve` enables package resolution relative to the installed SDK). No provider credentials or inference are used. `broker.resolve(signal)` is a narrow typed Result port; one test passes it through the real orb-runtime `McpCredentialResolver` with a fake token endpoint, clock and checkpoint task. This does not test the production token endpoint, control-plane broker, provider OAuth or consent. Tests capture accepted writes independently from HTTP attempts. Each HTTP fixture binds an OS-assigned loopback port and closes clients and sockets.

**Native SDK extension:** `createMcpExtension` consumes an injected authorized snapshot through `loadConfig`, and `createTransport` supplies per-request broker credentials. A 404 rejecting a session triggers one reinitialization and one retry (two attempts, one accepted write) **only when the transport class shares the coding-agent's installed pi-mcp module identity**. This isolated npm lock nests a second copy of pi-mcp 0.99.1 under coding-agent; importing the top-level package creates a different `McpSessionExpiredError` class, which fails native `instanceof` recognition (one attempt, zero accepted writes). Both outcomes are executable tests. The aligned test uses the package's public ESM export resolved relative to coding-agent, not private dist imports. Node currently requires the experimental parent-URL resolver flag; this proof is not a production integration recommendation. SDK extension testing also confirms an accepted write followed by response loss is **not** retried (one attempt, one acceptance), and awaits `session_shutdown`/DELETE cleanup.

**Real runtime resolver + native SDK extension:** same-connection token cache is reused; advancing the injected clock into the 30-second expiry window fetches a new generation. On 401 the rejected generation is reported to the resolver; no same-request replay occurs, the next explicit call obtains a newer generation, and a successful response resets recovery so a later rejected generation can recover. The fake endpoint records rejected-generation arguments and the HTTP fixture records bearer tokens and accepted writes. The first test failed before the typed broker-port adaptation (`evidence/resolver-red-first.tap`).

**Low-level McpClient/StreamableHttpTransport:** per-request token rotation on a persistent connection, static headers, GET-stream credentials, 401 rejection without guest auth provider or same-request replay, later explicit token recovery, failed-response-body redaction, disabled redirects, accepted-response loss without replay, resource pagination, templates and read. Low-level behavior does not prove native extension retry or optional unsupported-template handling. Startup-outage observability, native OAuth-provider 401 replay, real token-endpoint networking, and provider authentication remain unqualified.

`evidence/resolver-red-first.tap` preserves the first resolver integration failure. `evidence/transport-red-first.tap` preserves the contract failure before the adapter existed; `evidence/transport-red-resources.tap` preserves the first resource-pagination fixture failure; `evidence/transport-failure-evidence.tap` preserves the original 404 module-identity failure. They contain no tokens or remote response bodies.
