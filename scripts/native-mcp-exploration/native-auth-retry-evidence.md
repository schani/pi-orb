# Native broker auth retry proof

Run: `cd scripts/native-mcp-exploration && node --import tsx --experimental-import-meta-resolve --test --test-timeout=60000 native-auth-retry.test.mjs` (7 pass). Uses published Pi 0.99.1 `AuthProvider` and SDK-owned `StreamableHttpTransport`, real `McpCredentialResolver`, fake token endpoint and loopback HTTP fixture; no provider credentials or guest token file.

`AuthProvider.token()` returns undefined; its `onUnauthorized()` only enables Pi's bounded retry. The custom fetch resolves CP-brokered credentials with the HTTP attempt's AbortSignal, rejects the exact 401 generation, and injects the access token. This split is necessary because the published auth callback has no AbortSignal. Pi retries the same POST after 401: two attempts, newer token, one accepted write. A second 401 stops at two attempts; no custom retry loop. A 403 carrying `Bearer error="insufficient_scope"` retries once with the same token; an ordinary 403 does not. The 403 does not trigger broker rejection, guest consent, or scope escalation. The wrapper preserves the challenge header solely for Pi's parser, discards upstream error bodies, and returns sanitized error text. Cancellation before credential resolution completes sends no POST; an accepted write whose response is lost is not replayed.

These tests exercise low-level native transport and its auth hook, **not** the coding-agent session/extension path. Production control-plane refresh and browser consent are not exercised. The challenge header is untrusted protocol metadata; this adapter passes it to native parsing but does not follow its URLs or echo it in the thrown error.
