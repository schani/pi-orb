# Web UI

The UI must support two modes without visibly changing data sources:

- **Stopped/unavailable orb:** show the complete replicated history from the control plane database.
- **Active orb:** first show database history, then attach live updates after the database cursor while the host may still be starting.

The first UI needs to display at least:

- user and assistant text as Markdown, for both committed history and live streaming;
- reasoning/thinking when available and permitted;
- tool-call and tool-result status, with inputs and outputs available only through collapsed disclosures by default;
- compaction summaries;
- persisted and live user-shell commands as preformatted command/output blocks, including exit, cancellation, truncation, and excluded-from-context status;
- runtime state such as starting, working, idle, stopped, or failed;
- on a running orb, the floating interactive terminal specified in `docs/terminal.md`, kept separate from persisted composer shell records.

Remaining UI questions include rendering unknown content blocks, large/truncated tool output, and image storage. Transient token deltas are ephemeral presentation events and are reconstructed after reconnect through ordinary live events; they are not stored in PostgreSQL.

## Missing resources (decided 2026-08-08)

A direct URL for a resource that does not exist stays at that URL and renders a resource-specific message (for example, “Orb doesn't exist”) with a link to the dashboard. Silently redirecting to the dashboard was rejected because it hides whether the resource was deleted, the URL is stale, or navigation failed. This behavior applies consistently to every resource type and to unknown application routes; unknown routes render “Page doesn't exist.”

## Comprehensive frontend failure handling (current proposal, 2026-09-03)

A field report found that submitting a message after the Google IAP browser session expired appeared to do nothing; reloading then entered Google authentication. The current HTTP adapter collapses a failed IAP redirect/CORS exchange into a generic network error, and the orb page renders mutation errors above the transcript, far from the sticky composer where the user is looking. This is a general failure-model and placement defect, not just missing auth copy.

The proposed model has one typed browser transport boundary and small UI state machines rather than a notification framework or query-cache dependency:

- classify `auth_required`, `offline`, `timeout`, validated control-plane HTTP errors, invalid responses, WebSocket protocol failures, cancellation, and unexpected framework failures separately; user-facing copy is derived from those facts rather than embedded in the adapter;
- test IAP's documented AJAX behavior (the `X-Requested-With` request signal) against the live deployment and use an explicit 401 as the primary expired-session signal if validated; because browser WebSockets cannot set that header, classify a suspicious live/terminal socket close with a bounded same-origin HTTP probe rather than guessing that every disconnect means expired auth;
- route by scope: auth is persistent app-wide state, a foreground mutation owns an error adjacent to its initiating control, a failed initial read owns the page, and polling/socket degradation marks data stale or reconnecting without repeating banners;
- cover every browser boundary, not only conversation submission: route-critical project/orb/history/message reads; partial project-orb, secret, and search reads; project/orb create and rename forms; secret writes; start/stop/archive/delete lifecycle mutations; shell and abort requests; background polls/history refreshes; agent and terminal WebSockets; and local Clipboard, FileReader, Notification, and React render boundaries. A shared transport classifier is exhaustive, but a generic global error queue is rejected because only the operation owner knows whether to preserve a form, mark a section stale, reconcile an ambiguous mutation, or retry;
- preserve user intent until success is authoritative. The composer clears only after the durable message `202`; a transport timeout says the result is unconfirmed, not that the server did not receive it; retries reuse the exact message ID and body. Other ambiguous mutations reconcile their resource before offering retry unless their contract is idempotent;
- enter IAP reauthentication through a same-tab top-level reload; opening another copy of the app was rejected after field testing because it left the original tab visibly expired and made recovery appear ineffective. The orb composer persists its per-orb text, mode, and image attachments in tab-scoped session storage and restores them after the round trip; other recoverable forms must gain equivalent scoped preservation before this broader proposal is complete;
- add bounded deadlines to foreground HTTP calls, ensure every pending action reaches a terminal reducer state, and put a route-level React error boundary around unexpected render failures while keeping expected failures in `Result` values;
- expose sanitized copy plus a correlation/diagnostic identity when available. Record transport class, route template, operation kind, build, and recovery outcome without message text, secret values, URLs carrying user input, or attachment bytes. Authentication telemetry may be blocked by IAP and can be submitted only after connectivity returns; IAP access logs remain the authority for intercepted requests.

**Session-expiry presentation decided and implemented 2026-09-03.** Use the **Session ribbon**: a persistent app-wide strip above the route chrome says `session expired` and offers **sign in again**. The 2026-09-03 second line warning that changes and live updates may be paused was dropped on 2026-09-04: a strip that stays on screen until sign-in already says the session is not working. A 401 from any browser API request activates it. Every API request sends IAP's AJAX signal (`X-Requested-With: XMLHttpRequest`) so expiry returns a classifiable 401 instead of a Google redirect flattened into a CORS/network error. Live unauthenticated probes on 2026-09-03 confirmed the real edge returns HTML `302` to Google without the signal and HTML `401` without a redirect with it (`docs/testing.md`). The sign-in action performs a same-tab top-level reload, allowing IAP to run its ordinary Google redirect and return directly to the requested hash; opening a second app tab was rejected after field testing because it neither repaired nor cleared the original tab. Non-empty composer text, explicit mode, and image attachments are mirrored to per-orb `sessionStorage`, removed after the composer returns to its empty message state, and restored after reload; a storage denial or quota failure is contained at that browser boundary and shown in the orb's existing notice surface rather than silently promising preservation. Whenever a still-mounted window regains focus it also calls the state-free `GET /api/v1/session` reachability probe, and a request begun after the last 401 must reach the application before the ribbon clears. Request sequence ordering prevents an older concurrent success from incorrectly clearing a newer auth failure. The compact orb header and the project index remain sticky immediately below the ribbon.

The ribbon communicates the shared authentication cause; it does not replace operation-local outcomes. Existing action errors remain where the operation owner can say whether a form was preserved, a mutation was rejected, or an outcome is uncertain. Generic transient toasts are rejected as the primary treatment because they disappear, detach from the affected action, and are easy to miss. A modal is reserved for an operation that cannot safely leave the current state, not ordinary session expiry. [`design-prototypes/frontend-error-handling.html`](../design-prototypes/frontend-error-handling.html) contains the implementation plan, complete request-coverage map, failure matrix, selected Session ribbon, and four alternatives. The remaining comprehensive operation-local work is tracked in `TODO.md`.

## Frontend-only development (decided 2026-08-06)

Two Docker-free development compositions exist and must not be confused:

- **Full service with process-hosted orbs:** run `npm run dev:local` for the control plane/SQLite/process supervisor and `npm run dev --workspace @pi-orb/web` for the normal web server. This exercises real Pi runtimes, lifecycle, protocol, replication, credentials, and model inference, but runs repository code unsandboxed (`docs/host-provider.md`).
- **Frontend-only fixture:** run only `npm run dev:frontend`. Vite replaces the HTTP/WebSocket backend in process; no control plane, database, orb process, Pi session, or model call exists.

The web workspace's in-process fixture is activated by Vite's `frontend` mode. Run it with:

```sh
npm run dev:frontend
```

This starts only Vite and needs no PostgreSQL, Docker, control plane, runtime, credentials, or model service. It is not the frontend command for `npm run dev:local`; that full-service composition uses the normal `npm run dev --workspace @pi-orb/web` command in a second terminal. The fixture owns the `/api/v1` HTTP routes and live agent/terminal WebSocket upgrades on the Vite server. It starts with one running orb and a short conversation, a starting orb with an OpenAI device-login challenge for testing the authentication UI, and an archived orb so the dashboard's archive shelf is visible immediately; messages receive a simulated streamed echo, user-shell commands receive simulated streamed command output and persisted `pi.bash_execution` records (including excluded-context state), the floating terminal receives a deterministic binary echo/prompt over the real terminal controls, and start, stop, project/orb creation, history reload, and abort use the real browser-facing contracts. Newly created fixture orbs remain in `creating` for about 10 seconds before becoming `running`, so the editable-while-send-is-unavailable composer behavior can be exercised manually.

The fixture includes a small fixed **frontend fixture · session active** development control in the lower-right corner. **expire session** changes only the fixture transport boundary: it terminates fixture WebSockets and makes every `/api/*` request return an IAP-like HTML 401; **restore session** admits requests again. Reloading the page while expired—what the real ribbon action does—skips an external identity page, restores the fixture session, and returns to the same hash, modeling a successful same-tab IAP round trip. Manual toggles also dispatch an ordinary window-focus event, so production `SessionRibbon` code performs its real `/api/v1/session` probe and state transition. The control and its private `__pi_orb_fixture` endpoints are injected by the Vite plugin and do not exist in the React tree or production build. `npm run test:e2e:frontend` drives this exact fixture control in Chromium and proves HTML-401 detection, ribbon visibility, same-tab load, hash retention, session recovery, and composer-draft restoration.

The fixture is a transport-level adapter, not a mock branch in React. Production UI code still calls the same relative HTTP URLs, validates the same `@pi-orb/protocol` schemas, and runs the same WebSocket reducer. This keeps frontend-only behavior representative and makes protocol drift fail visibly. It is intentionally ephemeral and process-local: restarting Vite resets all fixture data, and it is for manual UI development rather than backend or E2E correctness. Normal `npm run dev --workspace @pi-orb/web` retains the proxy to the real control plane.

## Per-orb browser-tab identity (decided and implemented 2026-08-09)

Once the orb and its parent project have loaded, the orb chat route sets the HTML page title to `{project name} · {orb name}` so multiple open orb tabs are distinguishable. An orb that has not yet been auto-named uses `untitled orb` as its name. While either resource is loading, after leaving the orb route, and for missing resources, the title is the neutral `pi-orb`.

## Per-orb favicon status (decided and implemented 2026-08-07)

The orb chat route makes its coarse state visible in the browser tab through a small, static set of SVG favicon variants derived entirely in the web client from state it already has; this requires no API or runtime-protocol change. The project-list route and an orb that has not loaded use the neutral pi-orb mark.

For an orb route, `stopped` gets the stopped variant; `running` gets the running variant; and a `running` orb with an open live connection reporting `activity: busy` gets the busy variant. Busy has priority over running. A disconnected or reconnecting tab must not present stale runtime activity as current, so it falls back to running until synchronization reports busy again. Transitional (`creating`, `starting`, `stopping`) and `failed` lifecycle states have distinct variants rather than being mislabeled as one of the three primary states.

The marks remain distinguishable at 16px by glyph/fill as well as color and avoid animation. Running/idle uses light green to suggest that the orb is ready for the user; busy uses the darker UI green, not the error-associated terracotta. `index.html` installs the neutral icon before React loads. Mounting an orb page updates that one icon link rather than accumulating links; leaving the route restores neutral. The pure status mapping and link replacement are unit-tested in `apps/web/src/lib/favicon.test.ts`; the SVG assets live under `apps/web/public/favicons/`.

## Dashboard orb update age and ordering (decided and implemented 2026-08-26; placement revised 2026-09-04)

Every dashboard orb shows its age since last update, not since creation, as one number and a one- or two-letter unit suffix (`12s`, `41m`, `3h`, `2d`, `3w`, `1mo`, `1y`), without a timestamp, leading separator, or `ago` suffix. The largest whole useful unit is selected from seconds, minutes, hours, days, weeks, months, and years; anything under a second reads `1s`. Word units (`14 minutes`) were retired on 2026-09-04: age is a right-aligned column on a 316px project column and a 236px index, where the unit is the only word that fits. Ages refresh every ten seconds while the page remains open, so a sub-minute age is never more than ten seconds stale. Within a project, orbs are sorted by `updatedAt` descending so newly created and most recently changed orbs appear first. Abbreviated orb hashes are not shown.

Age has one fixed place: the second line of the two-line orb entry (`orderProjects` and `formatProjectOrbAge` in `apps/web/src/lib/project-orbs.ts`). The 2026-08-26 pair of treatments — inline after the title on a wide shelf, on a subline in a narrow one, selected from [`design-prototypes/orb-age.html`](../design-prototypes/orb-age.html) and switched by a shelf-scoped CSS container query — is retired: project columns are a fixed 316px, so there is no width for the treatments to adapt to and no reason to pay for a container query.

Projects themselves are ordered by their most recently updated working orb, descending; projects with no working orbs follow; a `deleting` project sinks last, and New Project is always the final cell. The order is a pure function (`orderProjects`) over the loaded project list and orb lists, so it is unit-testable and stable while orb lists are still loading.

## Dashboard Find (decided and implemented 2026-08-26; presentation revised 2026-09-04)

The dashboard provides a route-scoped Command-K / Control-K Find for project names, GitHub repository URLs, and working or archived orb names. Generic app-search shell/core/source contracts let other routes add their own Command-K sources without coupling to dashboard resources. Every result is a real anchor: orb results use `#/orbs/:orbId`, while project results use `#/projects/:projectId`, an addressable focused-dashboard route that scrolls to and focuses that project. There is no persistent Find hint anywhere on the dashboard. Ordinary click, Command/Ctrl-click, middle-click, copy-link, and context-menu behavior remain native. The card maintains exactly one pointer/keyboard selection, ignores stationary-pointer events caused by result redraws, and replaces result sets without an empty-frame flash. A missing focused project stays at its URL and renders “Project doesn't exist” with a dashboard link. The complete architecture is in `docs/dashboard-find.md`.

The **Index card** presentation of 2026-08-26 (`design-prototypes/dashboard-find.html`) is superseded by the Signal / Boards modal: a 640px box with a 1px black border, 80px from the top over a 35% black scrim; line one is a `>` prefix column and the query input; matches are grouped under uppercase `PROJECTS` and `ORBS` headings in source order; each result is one 20px line of state glyph, name with the matched text bold and underlined, project chip, and age. The selected row is inverted. Retired with the card: the kind label column and result arrow (the group heading and the row's shape already say what a result is), the two-line result with a context subline (the chip and age carry the same facts on one line), the `↑↓ / ↵ / esc` legend and match count, the empty-query scope sentence, and the visible close control — the shortcut's owner does not need to be told how it works, and a press outside the card dismisses it, as Escape always has.

Partial status remains visible: when some orbs are still loading or failed to load, one quiet line under the results says so in a polite live region, because a Find that silently searches an incomplete index is indistinguishable from one that found nothing.

## Project secrets configuration (decided and implemented 2026-08-28)

The project-scoped, write-only secret contract is in `docs/credentials.md`. The dashboard uses the selected **Sealed card** presentation: a project-scoped entry point opens a focused modal over the still-recognizable dashboard, listing names and update ages but never values and supporting add/replace/remove. The card keeps project scope explicit and states that changes apply on the next orb start. It closes through its visible close control, Escape, or a successful same-context navigation; unsaved name/value input is not discarded by an accidental backdrop click.

[`design-prototypes/project-secrets.html`](../design-prototypes/project-secrets.html) preserves the original five-direction surface study: Inline ledger, Settings folio, selected Sealed card, Margin vault, and Paste desk. Sealed card was chosen because secret management is occasional and deliberate: it preserves dashboard location, focuses attention while a write-only value is present, and does not permanently enlarge every project panel or create a broader project-settings information architecture before one is needed. The batch paste direction was rejected initially because one malformed or accidentally repeated name could rotate several credentials at once; individual writes make each destructive replacement explicit.

**Entry placement revised and implemented 2026-08-31.** Use the selected **Identity metadata** treatment: a quiet key-marked `N secrets` link (`no secrets` at zero) sits directly below the repository URL and opens the Sealed card. The prototype's trailing `project environment` text is omitted as redundant, and the trailing `configured` was dropped on 2026-09-04: within a 316px project column the count is the whole message. The card itself lost three lines on the same date — the `configured` word repeated on every row, the `No project secrets configured.` empty sentence, and the footnote restating that values cannot be viewed and apply on the next start — because a listed name is configured, an empty list is empty, and the header line and the value field's placeholder already carry those two rules once each. This places the inventory with project identity while separating it from the right-aligned `new orb` action in position, shape, typography, and color. The former adjacent `secrets` text action is rejected because proximity and matching typography made occasional configuration look like a peer creation action. [`design-prototypes/project-secrets-entry.html`](../design-prototypes/project-secrets-entry.html) preserves this selection and the four rejected alternatives—Project command menu, Vault edge tab, Project utility footer, and Environment seal. Open question 46 is resolved in `docs/open-questions.md`.

## Visual design (decided 2026-09-04)

The UI uses **Signal / Boards**, selected from [`design-prototypes/signal-boards.html`](../design-prototypes/signal-boards.html). The exploration trail is [`design-prototypes/ui-redesigns.html`](../design-prototypes/ui-redesigns.html) (ten directions), [`design-prototypes/mono-minimal-variations.html`](../design-prototypes/mono-minimal-variations.html) (five typography variations of the selected monospace direction), and [`design-prototypes/signal-dashboard-variants.html`](../design-prototypes/signal-dashboard-variants.html) (three dashboard layouts). The prototype ships in its **wrap-fixed** overflow mode only; masonry, sideways scrolling, and the dense 220px column were rejected. The dashboard's weight problem — a board that looked unfinished at one project and thin at three — was studied separately in [`design-prototypes/signal-dashboard-substantial.html`](../design-prototypes/signal-dashboard-substantial.html) as six proposals: a full-height ruled board, a fleet strip with a system footer, large type, a recent-activity ledger, a fixed slot grid, and the combination that shipped (strip, footer, full-height columns, and moderate type). The combination won because it is the only one that holds at every project count without inventing content: the ledger and the slot grid both fill space with rows and boxes that say nothing new.

It replaces the "Reading Room" variant of the Manuscript × Gutter design, whose serif reading typography, warm paper palette (`#f8f3e9` / `#221c12` / terracotta), turn gutter with `Y`/`O` marks and rails, and rounded per-project panels were made for a reader being introduced to a product. There is one user, who already knows what this is; the dashboard's job is to say what every orb is doing at a glance, and the transcript's job is to be read. Light mode only remains an explicit product decision.

Decisions:

- **One face, one grid.** The existing system `--mono` stack (`ui-monospace`, SF Mono, Menlo, Consolas, Liberation Mono) at 13px on a 20px line, tabular numerals, everywhere. No webfonts. Headings are uppercase bold with `letter-spacing: .08em`. Size ranks exactly two things, both on the dashboard board and both since 2026-09-04: the project name and the New Project heading at 18px on a 24px line, and the orb name at 14px on a 22px line. Everything else, including every other heading, stays at 13px on the 20px line.
- **White ground, black ink, three greys, two signal hues.** `--w #fff`, `--k #000`, `--g1 #f2f2f2` (fills), `--g2 #999` (hairlines, disabled), `--g3 #555` (secondary text); `--ok #1a7e37` for alive-right-now and `--bad #b42318` for gone-wrong, each with a pale background. Every lifecycle state also owns a hue (`--st-busy/idle/start/stop/fail/arch/del`) used wherever that state appears.
- **1px black rules, `#f2f2f2` hairlines, zero radius, no shadows, no gradients.** Focus and the current row are inversion (black ground, white text), not a tint. Links are a 1px underline and invert on hover.
- **State is a glyph, not a word or a picture.** busy `●`, idle `○`, starting/creating/stopping `◐`, stopped `–`, failed `✕`, archived `▫`, archiving `◑`, deleting `…`, each in its hue, with the state word only as the glyph's `title`. A row carrying a state also carries a 2px left border in that hue, dotted while deleting. This retires the dashboard's favicon `<img>` marks and their hover tooltip: the SVG favicons remain the browser-tab status (above), but inside the page a text glyph sits on the line grid, needs no image request, and states itself.
- **One inline icon sprite** (`apps/web/src/components/Icons.tsx`, rendered once by the app shell): `pen`, `archive`, `bin`, `minus`, `x`, `copy`, drawn 14×14 inside 20×20 icon-only buttons with `aria-label` and `title`. Icon buttons never carry text; text actions (`new orb`, `stop`, `start`, `abort`, `copy` in prose) never carry an icon. **Every delete is red** and inverts to a red ground on hover.
- **No app header and no brand.** The dashboard is the home screen and renders as the page; the orb page identifies itself by orb and project name. A brand line repeated on every route is the clearest case of the UI talking about itself.
- **Projects are columns.** The dashboard is a grid of fixed 316px columns (`repeat(auto-fill, 316px)`, `grid-auto-rows: minmax(min-content, 1fr)`, `align-content: stretch`), left-aligned, columns separated by 1px black vertical rules and each row closed by a black rule; the page scrolls vertically. A column is a black-ruled header (18px name + rename pen on a 24px line; repo `·` secrets; `new orb` + red bin) over its working orbs, then the archive footer. Fixed width was chosen over fluid columns and masonry because a project column is a list of short lines: fluid columns stretch names across dead space, and masonry reorders columns as data changes, which destroys the muscle memory of where a project sits. 316px, widened from 300px on 2026-09-04, is what the larger project name needs before it starts truncating.
- **The board fills the viewport between two 24px lines (2026-09-04).** A **totals strip** rules the top: four tabular cells separated by 1px black vertical rules — `N PROJECTS`, `N ORBS`, `N BUSY`, `N FAILED`, bold number and uppercase grey label — counted in the browser off the loaded projects and orb lists (`dashboardTotals` in `apps/web/src/lib/project-orbs.ts`); orbs, busy, and failed count the working set only. A project whose orb list is still in flight contributes nothing yet and gets no placeholder: the strip states what is known, and a number that briefly rises is honest about a list still arriving. A **footer** is held against the bottom of the viewport, stating `<host provider> host · <database kind> · v<version>` in grey from `GET /api/v1/system` (`docs/control-plane-api.md`); before it answers the footer is an empty line, present but silent, so nothing below it moves. The footer says nothing about the fleet — a count of booted hosts would repeat the strip and go stale between reloads. Between the two, the board carries `min-height: calc(100dvh - 48px)` and stretches its rows into it, so a column holding one orb still rules from the strip down to the footer instead of leaving the lower two-thirds of the screen as blank paper.
- **An orb entry is two lines** behind its 2px hue: a 22px line of glyph and 14px name (bold when busy or failed, grey when stopped or archived), then a 20px line of age with the archive and red delete icons right-aligned, with 4px of padding above and below so entries read as blocks rather than a continuous ledger. A failed orb adds a third red line carrying `lastError`, so the reason a boot failed is on the dashboard rather than one navigation away. A deleting orb adds its cleanup blocker as a grey line.
- **The archive is a `<details>` footer** on `#f2f2f2` (`▸ archive · n`, `▾` when open), entries in the same format with delete only. A project with no shelved orbs renders no footer at all (2026-09-04): an empty shelf is a line spent saying nothing. This keeps the 2026-08-09 separation of retained transcripts from active work and its state/action rules, but retires the side-by-side two-shelf layout, its `working set` / `archive shelf` headings, and its empty-shelf sentences: a column is already the working set, and a shelf heading in a 316px column costs a line to repeat what the rows show.
- **New Project is the last cell**, marked by a dashed left rule: `NEW PROJECT`, `project name`, `repository URL`, and a black `Create project` button. Keeping creation last, after every existing project, is unchanged from the 2026-08-08 "Compact strip" decision and for the same reason; the orientation sentence under the heading is retired.
- **Missing-resource and create-orb pages are plain lines** in the same language with a `Back to dashboard` link, and no header.
- **Two panes on the orb page.** A 236px project index with a black right rule sits beside the transcript column. The index is the orb's own project working set under the uppercase project name — the `n working` count was dropped 2026-09-04 because the rows below are the count — each row `glyph | name | age` behind its 2px state hue, the current orb inverted; it is fetched from the existing list-project-orbs endpoint whenever the open orb's project, lifecycle state, or activity changes — never on the 2-second inbox poll, which would spend a project-wide list request every tick on a list that moves rarely — and its rows appear once it has loaded. Its first row (2026-09-04) is a 24px `PI-ORB` linking to the dashboard, above the project name and under a black rule, so the index renders even before the list arrives. The dashboard gets no brand line: the choice among a full-width brand bar, this index row, and a breadcrumb orb header ([`design-prototypes/signal-brand-line.html`](../design-prototypes/signal-brand-line.html)) took the index row because it adds no line to the transcript column and keeps the link in the same top-left corner on both screens. The index scrolls itself while the transcript scrolls the document, so window-level scroll pinning is unchanged. A `new orb` link below the working-set rows uses the same project-scoped creation route as the dashboard (2026-09-04). There is no app header and no find on this route.
- **A 24px sticky orb header:** orb name and rename pen | state glyph in its hue with the state word (and `· busy` when the runtime reports activity) | `start`/`stop` as text, archive icon, red bin. The project chip was dropped 2026-09-04: the index beside the header already carries the project name. `start` and `stop` render only when the state accepts them rather than sitting there disabled. Orb id, state version, checkout commit, preview host/ports, live connection text, and notification controls stay omitted as clutter. Lifecycle and authentication diagnostics remain immediately below the header, each a 1px black box on the transcript's `···` system prefix; since 2026-09-04 the device-login notice says `expires in 9m` rather than the raw expiry timestamp, and says nothing once the code has expired. The former archived notice (`this transcript is read-only and the orb can never be started again`) is retired: the header glyph says `archived`, and the absent composer and absent start action say the rest.
- **A record is a `32px` prefix column and a body.** The prefix is the speaker — `you`, `orb`, `sh`, `···` — replacing the `Y`/`O` gutter marks, their rails, and the `You`/`Orb`/`Shell` labels. A user turn is a full-width `#f2f2f2` band that includes the prefix column, closed by `#999` hairlines; an outstanding queued/steering/delivered/failed message uses the same band muted behind a dotted 2px left border with its status word as the only label. Agent turns are white. Compaction is a full-width CSS rule with `context compacted` inline in grey over the existing summary disclosure. A persisted shell block is a 1px-bordered `! command` block with its output and a grey `·`-joined status footer.
- **Markdown in the transcript** uses the one 13px face: `h1`–`h6` are uppercase bold at body size, inline code sits on `#f2f2f2`, and a fenced block is a 1px black box whose header line names the fence language and carries the copy action at its right.
- **Live streaming ends in a blinking 1ch black block cursor**, which is the only claim that the agent is still producing output; the former `working…` line is retired as a restatement of the header's state.

- **Consolidated tool activity (decided and implemented 2026-08-12; presentation revised 2026-09-04).** Consecutive tool calls render as the selected **Activity Rail** direction from `design-prototypes/tool-call-consolidation.html`: one collapsed summary per available semantic category inside the agent turn. Each category is a 1px-bordered 20px row — `▸`/`▾` marker | `label · headline` truncating to one line | metric right — and reasoning renders through the same `ActivityRailRow` component and CSS geometry, not a parallel lookalike, so marker position, row height, and columns cannot drift by category. Reasoning's label is `thinking`. A category of exactly one call names the actual file or command in its headline instead of `1 file …` / `1 command ran`, with the full value as the native title tooltip; larger runs drop the headline and count in the metric (`2 ran`, `2 files`, `+42 −7`). Read summaries count distinct paths: repeated reads of one file show that file's path exactly as a singleton read would. Expanded rows append their requested line range (for example `provider.ts:180–329`) so separate calls to the same path remain distinguishable. A completed category with nothing to report shows no metric; the former `complete` word was noise. Do not invent categories for tools the agent does not have; unknown tools retain a name-based fallback category. An expanded body sits on `#f2f2f2`: per-file rows keep their own output disclosure, while each command is a flat block — `run` prefix, bold command, output, and a green `✓ completed` or red `✕ failed` footer — because a command's output is what the reader came for. Parallel-execution wrappers have no presentation of their own. A maximal run ends at visible assistant prose, a user record, or another visible non-tool boundary. Live calls use the same category rail with running/completed/failed state, omit unavailable arguments and output, and colour marker, label, and metric by outcome: running green, failed red, completed neutral except explicit success signals. Live calls disappear once their persisted call ID is present so the live-to-history handoff never duplicates a call. Live reasoning, output, and tool state extend the final persisted agent record whenever no user/shell boundary intervenes; they must not create a second orb record merely because the persisted/live handoff occurred mid-operation. An exact persisted text/reasoning block suppresses its matching transient block during that handoff.

- **Composer (presentation revised 2026-09-04).** Sticky at the viewport bottom, full-bleed inside the transcript column, opaque so records scrolling behind it never bleed into the input. It is one row plus any attachments: a bold prefix column, the textarea, and — right-aligned, level with its first line — the `abort` text action when an operation can be aborted. There is no send button (removed 2026-09-04): ⌘⏎ / Ctrl⏎ is the only send gesture, and a pending request shows nothing. The placeholder is `Message the orb…` in message mode and `Run a shell command… (⌘⏎ to run)` in the shell modes; the message placeholder's 2026-08-05 paste-images and ⌘⏎ hints were dropped on 2026-09-04 as help text. **The prefix glyph carries the mode (2026-09-04):** `>` for message, `!` for shell, `!!` for excluded shell, in the same 32px column as the transcript prefixes. The bracketed mode chip and the second composer line are retired — the glyph the user just typed says the mode, and a chip repeating it beneath was the same fact twice. The `message` / `shell` / `excluded shell` status text survives only as a visually hidden `aria-live="polite"` region for assistive technology. Chat scrolls in the normal document flow with bottom-pinned auto-follow (scroll pinning in `apps/web/src/lib/scroll-pin.ts`). Auto-follow runs before paint and distinguishes delayed programmatic scroll events from reader scrolling, so rapid consecutive appends cannot incorrectly release the pin. Opening or creating an orb focuses the textarea without scrolling the document; submitting keeps focus there so the next message can be written immediately. The textarea starts at four lines and can be resized vertically, never below four lines (2026-09-04). With the send-anytime inbox (`docs/runtime-protocol.md`), message-mode send remains enabled while busy, starting, stopped, or failed; acceptance clears the composer only after the durable HTTP `202`, and each outstanding message appears exactly once in transcript position as a muted user turn labeled `queued`, `steering`, or briefly `delivered` until the corresponding runtime history record replaces it. The 2-second outstanding-message poll discards responses from requests that started before the last successful enqueue (mutation-epoch guard in `apps/web/src/lib/queued-messages.ts`, decided 2026-08-11), so a stale in-flight snapshot can never clobber an optimistically appended just-sent message. If several submissions were waiting when dispatch became possible, their separate turns collapse into one committed user turn with an empty line between the original messages. Shell modes remain enabled only on an idle live runtime.
**Field finding and fix (2026-08-12) — monotonic delivered inbox/history handoff.** The browser filtered a message out of its polled inbox state as soon as `GET .../messages` reported `delivered`. That status is committed by replication before the browser has necessarily applied the matching `history.record`, so independent inbox-poll and live-WebSocket schedules created a blank interval; if the live record was missed during a connection gap, the message and response stayed absent until reload loaded database history. The browser now retains every delivered row as a provisional turn until a locally applied native history record names it in `details.messageIds`. Seeing delivered without that record immediately refreshes database history; the refresh merges the replicated prefix ahead of any newer live suffix instead of replacing live state. Deterministic tests cover delivered-before-history, identity-based retirement, and prefix/live-suffix merging. The full unit suite and process-provider E2E pass; Docker-backed E2E could not run in the implementation environment because the Docker executable is unavailable.

- **Shell composer modes (decided 2026-08-05; face rule retired 2026-09-04).** The composer stores explicit `message | shell | excluded_shell` state, shown as the prefix glyph and announced as exactly `message`, `shell`, or `excluded shell`. The `!`/`!!` prefixes are editing gestures rather than visible textarea content: typing `!` at offset zero changes message → shell, then shell → excluded shell, without inserting a character. With a collapsed caret at offset zero, Backspace reverses excluded shell → shell → message without deleting command text. Pasting/replacing the whole input with leading `!`/`!!` normalizes to the corresponding mode and prefix-free body. The former serif-versus-monospace face switch is gone: the UI has one face, and the prefix glyph plus the placeholder already state the mode. An empty shell command cannot be submitted. Image attachments may remain when entering shell mode, but any attached image prevents shell submission and shows validation feedback; nothing is discarded silently. An accepted send clears the body and returns to message mode; rejection or disconnection preserves body, mode, and attachments.

- **Project working set and archive (decided 2026-08-09; activity revised 2026-08-13; presentation revised 2026-09-04).** Each project divides its orbs into a primary working set and an archive. `archiving`, `archived`, and `deleting` orbs occupy the archive; all other lifecycle states remain in the working set. Every entry carries the text state glyph immediately left of the orb name, with the state word as its `title`. Lifecycle state selects the stopped, transitional, failed, or running glyph; a running orb whose ordinary API snapshot reports `activity: busy` uses the busy glyph rather than being mislabeled idle/running. Unknown activity falls back to running. The dashboard deliberately does not poll or open a push channel for activity yet, so this observation changes on an ordinary dashboard resource reload. Actions are rendered only when the state accepts them: working rows offer archive and delete, archiving/archived rows offer delete only, and deleting rows offer neither. This was selected from five project-list prototypes; the separation keeps retained transcripts accessible without letting a growing archive dominate active work.

- **Open-tab turn notifications (decided 2026-08-06; header control removed 2026-08-08; in-page diagnostics removed 2026-08-14).** Notification state and permission controls are not shown in the compact orb header. On first opening an orb page with permission still at the browser's `default`, it immediately requests notification permission; browsers that require a user gesture may suppress that best-effort request, and the UI does not spend persistent header space on a fallback control. Every live Luna `turn_notification` attempts an OS notification when permission is granted, including while the orb page is foregrounded — suppressing foreground notifications was rejected after it made a manual completion test appear broken. The resulting shown/skipped/failed decision is written to the browser console but does not produce an in-page banner; desktop-notification status banners were removed because they clutter the conversation after every turn. The Notification API generally works on HTTPS or localhost, not the plain-HTTP tailnet development URL. The notification title uses the orb's current user/auto-generated display name when present and falls back to `Orb <id>` only while unnamed. Because first-turn auto-naming runs concurrently, receipt of `turn_notification` performs one ordinary orb-resource refresh before constructing the notification; a ref supplies the last known name if that refresh fails, without reconnecting the live socket when naming completes. The orb/operation pair is the notification tag and local deduplication key; clicking focuses and navigates to the orb. Same-tag browser replacement suppresses duplicates from multiple open tabs. Notifications are deliberately best-effort: no service worker, Web Push subscription, persistence, or reconnect replay exists, so closing all orb pages means receiving no notification.
- **Chat Markdown and URL linkification (decided and implemented 2026-08-05).** User and assistant messages use the same GFM Markdown pipeline in committed and streaming content. Its autolink-literal extension makes web URL literals clickable while composing with the syntax tree, so code spans/blocks and existing link syntax are never linkified a second time. Displayed custom messages, reasoning, and compaction summaries remain literal non-Markdown text and pass through a dedicated URL tokenizer instead of an ad-hoc regular expression. Only HTTP(S) and `www.` web URLs are linked; email and other schemes remain text. Generated external links open in a new tab with `noopener noreferrer`.
