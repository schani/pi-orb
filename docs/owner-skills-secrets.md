# Owner skills and secrets

**Requirement (2026-10-26):** the owner adds skills (`SKILL.md` roots with optional support files) and secrets outside any project; they apply to all of the owner's projects.

**Status:** Settings tabs deployed 2026-10-26 (Deploy run 40277646564, `c812b034`). GitHub pinned snapshots and draft-row proposal 3 approved 2026-10-27 (PDT; question 84); implementation under qualification, undeployed.

## Decisions (2026-10-26)

- **Surface:** proposal 1. The dashboard gear's Settings has Instructions · Skills · Secrets · Git · Claude. The Secrets tab is the project Secrets component (`ProjectSecretsSettings`) itself, not a lookalike; the Settings frame's `.personal-instructions-dialog form` column rule is scoped to the Instructions editor so it cannot restack the secret form. Skills reuse the MCP workbench disclosure: one row per skill expanding to its raw `SKILL.md`, explicit Save, `Saved · next orb start`.
- **Scope and adoption:** owner-scoped like personal instructions (`docs/personal-instructions.md`). Every orb of every project the owner has receives them at the next agent-context open / orb start. Saving never wakes, restarts or interrupts an orb.
- **Secrets:** write-only environment variables with the project-secret name rules, reserved names and limits (`docs/credentials.md`). The project-secret domain logic is generalized, not forked: owner bundles `{userId, revision, values}` live in their own GSM parent `pi-orb-credential-user-secrets`; `user_secret_pointers` holds metadata and the exact version. The existing runtime secrets route returns owner values overlaid by project values, so **a project secret with the same name wins** and the runtime is unchanged. MCP bearer references remain project-only.
- **Skills:** stored one row per skill in `user_skills(user_id, name, content, files, source, updated_at)` (migration 052); no revision column. Name and description come from the frontmatter (no separate name field), parsed with Pi's strict YAML parser: name `^[a-z0-9]+(-[a-z0-9]+)*$` ≤ 64, description ≤ 1024, content ≤ 64 KiB, at most 100 skills. `POST /api/v1/owner-skills` creates; `PUT /api/v1/owner-skills/:name` replaces and renames in one transaction when the frontmatter name differs; `DELETE` removes. Bundled platform skill names are rejected at save.
- **Precedence (user decision):** **owner skills win** over same-named repository skills, silently, in both harnesses. Pi omits the repository skill; Claude Code's native personal-over-project rule gives the same result for skills materialized into its user skills directory.
- **Rejected simplifications of an earlier plan:** a single jsonb row per user (needs CAS for two concurrent edits; one `SELECT` already gives a consistent set), an owner-skills adoption history record (Pi already persists the rendered skill inventory in the prompt section), a shadowing warning, a 1 MiB total cap, a separate owner-secrets runtime route, and a duplicated secrets domain.

This reverses the earlier Pi resource-scope decision that user-level skills are outside required resource scope (`docs/pi-durable-evaluation.md`).

## GitHub skill imports (2026-10-27, PDT)

**Status:** implemented locally, undeployed. Scoped qualification and first failures: `docs/testing.md`; full exact-source deployment gates remain in `TODO.md`.

**User requirement:** add an owner skill from a GitHub folder URL, including `https://github.com/schani/agent-skills/tree/main/nasa-handbook/skill`, and explore five Settings-modal designs. The user approved pinned whole-folder snapshots, persisted support files/source metadata, and draft-row source mode (proposal 3).

**Finding:** the NASA folder at `d14a8e525c6708b5f481661f483aab52b06def02` contains 22 files totaling 2,423,810 bytes; the largest is `assets/examples/pi-durable-overview.png` (466,567 bytes). Its instructions require scripts, templates, fonts, references and PNG examples. These need real guest files: central resource-reader image support alone cannot make fonts available to shell commands or execute scripts. This rules out importing only `SKILL.md`.

**Decision — scope:** public GitHub folder URLs; import the complete folder once, resolving the ref to one commit before reading files. Add sends the preview's URL and exact SHA; the URL fixes the folder path, and Add never re-resolves its mutable ref; the server retrieves and revalidates those bounded bytes rather than trusting browser-supplied files. No signed preview tokens, database drafts, automatic synchronization, boot-time GitHub dependency, install hooks or dependency installation. Preserve owner scope, precedence and next-context adoption; importing never restarts an orb. Failed imports leave saved skills unchanged.

**Decision — approved persistence:** each `user_skills` row retains `content` as root `SKILL.md` and stores nullable source metadata `{url, commitSha}` and support files `{path, base64, executable}` with folder-relative paths. Save the complete bundle atomically under the existing owner lock. Recheck per-bundle and aggregate capacity against the resulting set on manual edits as well as imports; a larger root must not grow preserved support files beyond the bundle limit. Manual root edits and renames preserve support files and source atomically; source describes import origin, not a claim that edited bytes match upstream. Duplicate Add returns a conflict; there is no overwrite or reimport action. Derive integrity hashes rather than adding a revision system. Extend `NativeResourceContext`'s existing private `orb.resource-context` document (`apps/control-plane/src/adapters/durable/context-storage.ts`), whose managed snapshot already persists owner skill names/content; no new adoption store is needed. Publish exactly those captured bytes on every execution binding, including host replacement, before tools can execute. The prompt/resource reader and guest use `../.pi-orb/owner-skills/<setHash>/<name>` relative to `ready.cwd` (`workDir/repo`), placing the cache beside the checkout inside the existing retained workspace. This keeps global instructions/assets out of Git status and accidental commits without Git ignores or new configuration. After readiness, absolute and relative aliases resolve against the known cwd; those under the sibling root retain captured-read authority. Process retains/removes the enclosing host workspace; Docker retains/removes its `/workspace` volume; GCP retains/removes the data disk mounted at `/workspace`. These existing cleanup boundaries own the cache lifetime. Hash names, paths, bytes and executable bits; stage then atomically rename complete directories. Existing valid directories are verified; corrupt directories fail visibly with their path and remain untouched, without repair/quarantine or a new lock/GC mechanism. Automatic repair was rejected because it can remove a healthy directory during another binding. Global `/opt` roots were rejected because guest permissions and shared process-host ownership leak across contexts. Claude materializes the same bundle into its orb-owned personal skill directory at context open.

Root `SKILL.md` remains text and is non-executable (`0600`); support files retain the executable bit (`0700` executable, otherwise `0600`). No root executable metadata or arbitrary Unix mode round trip is promised. Pi distinguishes `installed` and `verified`, logging installation edges rather than healthy verification levels; failures use the existing user-visible error surface. Its expanded SHA-256 manifest is UTF-8 encoded once and sent through existing write/append operations in sequential 4 MiB byte chunks, below the execution server's unchanged 16 MiB request limit. No new persisted state or transport setting.

**Decision — URL/retrieval:** accept only `https://github.com/<owner>/<repo>/tree/<ref>/<folder...>`, without credentials, port, query or fragment. The first segment after `tree` is the ref; slash-containing refs require a full commit SHA URL instead, not heuristic ref/path probing. Decode segments once; reject encoded separators, dot segments and escaping paths. Use a constructed GitHub HTTPS repository URL, no credentials or redirects, and bounded Git commands in a fresh bare repository: no checkout, hooks, filters or inherited config. Read only the pinned subtree's blobs; bound time, output and pack size and clean up staging on failure. Reuse command helpers, not `GitResourceSource`'s HEAD selection, symlink-following selector or orb-keyed persistence.

**Decision — limits/API:** 8 MiB decoded bytes and 5,000 files per bundle, including root `SKILL.md` (still ≤64 KiB); 16 MiB decoded and 24 MiB serialized JSON for the owner's complete bundle set, retaining the 100-skill cap. Count actual encoded bytes, including base64, paths and metadata, under the existing owner lock on create/replace. This leaves headroom below a 32 MiB budget for owner-skill responses; combined snapshot/installation envelopes must account for platform/repository resources separately. GET and mutation list responses retain root content and lightweight source/file-count/size metadata, never support-file base64: copying bundles into the current full-list response would allow 100 × 8 MiB, over 1 GiB after base64. Preview needs only root content, manifest and totals; Add retrieves the pinned files server-side.

Reuse strict frontmatter validation, owner CRUD, snapshot readers and execution file operations. Reject symlinks, submodules, duplicate or conflicting paths and support entries named root `SKILL.md`; require normalized folder-relative UTF-8 paths ≤1,024 bytes. Preserve executable bits and font licences. Expose source commit and import/save/install failures in the existing disclosure or orb error surface. Pi retains its full adopted snapshot privately and content-free adoption/install lifecycle edges. Claude exposes native boot failures and retains its current materialized root; no Claude success/adoption history is added. The current source row and retained root do not reconstruct every historical Claude source revision.

**Five design directions:** [hosted study](https://files---pi-orb-issuer-1077475695242.us-central1.run.app/s/f80c5983-861b-49b6-9bb1-6683386edf7c/design/github-owner-skills/index.html).

1. **Inline URL:** a URL field above the disclosure list; smallest surface.
2. **Per-add source tabs:** GitHub / Write tabs in a new-skill composer; explicit but adds navigation.
3. **Draft-row source mode:** a source menu in the new-skill disclosure; reuses draft/error behavior.
4. **URL → review:** URL entry then folder review before saving; clearest inspection, extra step.
5. **Paste into raw editor:** recognize a pasted GitHub URL and offer explicit preview; least chrome, less discoverable.

Chromium smoke passed all five at desktop/mobile widths (1440/390px): preview/add/provenance/remove, retained error drafts, manual creation, keyboard/focus containment and no overflow. Simulation-only, not production import qualification; local captures: `.context/studies/github-owner-skills-9DViJE/`.

**HTTP/domain contract:**

- `POST /api/v1/owner-skills/preview {url}` resolves once and returns validated `name`, `description`, root `content`, `source: {url, commitSha}`, `manifest: [{path, bytes, executable}]`, `fileCount` and `totalBytes`. Counts/bytes include root `SKILL.md`; the manifest exposes no base64. Preview makes no database change.
- `POST /api/v1/owner-skills/import {url, commitSha}` retrieves the exact full 40-character SHA and URL folder again, revalidates, and creates atomically. It returns the lightweight owner list. No browser bytes, preview token or database draft is accepted.
- Saved list entries retain root content, description and timestamp, adding nullable `source`, `fileCount`, `totalBytes`. Runtime/adopted snapshots carry `{name, content, files: [{path, base64, executable}], source}`. Manual skills have `files: []`, `source: null`.
- Acquisition uses the cancellable `OwnerSkillSource.acquire(task, {url, commitSha?}, signal?)` port with typed `ResultAsync` errors and simulation boundaries. HTTP disconnect cancels acquisition. Import passes cancellation through the owner-lock wait and checks it immediately before mutation and before the transaction callback returns; cancellation then rolls back. Database commit is the cutoff: no cancellation-after-commit guarantee. Failed validation/acquisition/capacity checks leave saved state unchanged.
- Saved source identifies current import provenance; Pi's private captured context preserves adopted bytes. The Settings disclosure shows provenance and errors; installation failures use existing orb error surfaces. No prompt text change or restart/wake is part of import.

**Qualification boundaries (tests first):**

- Contracts/domain URL and bundle validation, then SQL/store and import routes: test branch movement preserves the preview pin, binary/executable round trips, failures without mutation and duplicate rejection.
- Pi/Claude delivery: DST concurrent import/edit/delete/adoption; verify identical central/guest bytes after host replacement and process-host root isolation.
- Chosen UI: draft retention and import errors; full `npm run test:e2e` is a deployment gate.

**Selection:** proposal 3; the others remain rejected UI alternatives. All retain the Settings frame and disclosure language. Alternatives not recommended: importing only `SKILL.md` (incomplete skill), fetching latest at each boot (drift and network dependency), or introducing a generic package registry/blob service (unneeded machinery).
