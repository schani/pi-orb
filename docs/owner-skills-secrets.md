# Owner skills and secrets

**Requirement (2026-10-26):** the owner adds skills and secrets outside any project; they apply to all of the owner's projects.

**Status (2026-10-26): Settings tabs selected (question 83); deployed 2026-10-26 (Deploy run 40277646564, `c812b034`).**

## Decisions (2026-10-26)

- **Surface:** proposal 1. The dashboard gear's Settings has Instructions · Skills · Secrets · Git · Claude. The Secrets tab is the project Secrets component (`ProjectSecretsSettings`) itself, not a lookalike; the Settings frame's `.personal-instructions-dialog form` column rule is scoped to the Instructions editor so it cannot restack the secret form. Skills reuse the MCP workbench disclosure: one row per skill expanding to its raw `SKILL.md`, explicit Save, `Saved · next orb start`.
- **Scope and adoption:** owner-scoped like personal instructions (`docs/personal-instructions.md`). Every orb of every project the owner has receives them at the next agent-context open / orb start. Saving never wakes, restarts or interrupts an orb.
- **Secrets:** write-only environment variables with the project-secret name rules, reserved names and limits (`docs/credentials.md`). The project-secret domain logic is generalized, not forked: owner bundles `{userId, revision, values}` live in their own GSM parent `pi-orb-credential-user-secrets`; `user_secret_pointers` holds metadata and the exact version. The existing runtime secrets route returns owner values overlaid by project values, so **a project secret with the same name wins** and the runtime is unchanged. MCP bearer references remain project-only.
- **Skills:** stored one row per skill in `user_skills(user_id, name, content, files, source, updated_at)`; no revision column. Name and description come from the frontmatter (no separate name field), parsed with Pi's strict YAML parser: name `^[a-z0-9]+(-[a-z0-9]+)*$` ≤ 64, description ≤ 1024, content ≤ 64 KiB, at most 100 skills. `POST /api/v1/owner-skills` creates; `PUT /api/v1/owner-skills/:name` replaces and renames in one transaction when the frontmatter name differs; `DELETE` removes. Bundled platform skill names are rejected at save.
- **Precedence (user decision):** **owner skills win** over same-named repository skills, silently, in both harnesses. Pi omits the repository skill; Claude Code's native personal-over-project rule gives the same result for skills materialized into its user skills directory.
- **Rejected simplifications of an earlier plan:** a single jsonb row per user (needs CAS for two concurrent edits; one `SELECT` already gives a consistent set), an owner-skills adoption history record (Pi already persists the rendered skill inventory in the prompt section), a shadowing warning, a 1 MiB total cap, a separate owner-secrets runtime route, and a duplicated secrets domain.

This reverses the earlier Pi resource-scope decision that user-level skills are outside required resource scope (`docs/pi-durable-evaluation.md`).

## GitHub folders (user decision, 2026-10-28; implemented locally, undeployed)

- Settings Add accepts Markdown or a public `https://github.com/owner/repo/tree/ref/folder` URL. One POST acquires once and saves atomically; no preview/refetch protocol. PUT edits/renames only the root, preserving files and provenance; DELETE removes the entire bundle. Lists return root metadata/content plus nullable `source: {url, commitSha}`, never binary files.
- Anonymous GitHub REST resolves branch/tag/SHA candidates longest-first (including plain or percent-encoded slash refs), continuing only on 404 or commit HTTP 422 with the exact `No commit found for SHA: <candidate>` message, with at most 32 normalized URL components. Commit and tree SHAs pin nonrecursive folder traversal, one recursive target tree and sequential raw-file downloads. Truncated trees, links/gitlinks, unsafe paths, missing root `SKILL.md`, non-UTF-8 roots and unsupported modes reject the whole Add. Requests forbid redirects, observe cancellation and share a 30-second acquisition deadline; rate-limit failures are recoverable and visible. Private repositories and credential brokering are outside scope.
- Migration 052 adds only `files jsonb NOT NULL DEFAULT '[]'` and nullable `source jsonb`. Each supporting file is `{path, base64, executable}`; root text remains `content`. `source.url` is the canonical **pinned** GitHub folder URL, not the mutable submitted branch URL; `commitSha` is the resolved commit. The existing per-owner lock validates the complete resulting set before writing.
- One shared bound protects import, store and runtime: the complete `{skills:[{name,content,files,source}]}` snapshot is at most **8 MiB serialized UTF-8 JSON**, with at most **1000 files including roots**. Existing 64 KiB roots, 100 skills, metadata/name rules and platform-name reservations remain. The single wire budget leaves headroom under the execution transport's 16 MiB request limit; there are no separate decoded/encoded budgets, chunks or configurable limits.
- Pi captures the entire bundle in its existing private managed context. A fresh ephemeral UUID gives canonical `../owner-skills/<captureId>/<name>` paths: virtual reads work before compute; absolute aliases use ready cwd afterwards. Before admitting tools, the existing authenticated incarnation-fenced execution RPC installs that captured snapshot outside checkout. One context-local promise per incarnation coalesces installs; failures clear it for an ordinary retry. A replacement host receives the same captured bytes, not the latest owner store.
- Pi execution and Claude's existing personal-skills directory share one local materializer. It validates before writes, rejects managed-root/parent symlinks and writes private regular files (0600, executables 0700). Failed installation blocks tools/SDK; typed invalid/I/O failures preserve filesystem diagnostics, and retry rebuilds only its derived directory. Existing workspace cleanup owns these files; Git stays unchanged. No manifests, integrity cache, rollback, adoption records or persisted capture IDs.
- Startup failures use existing boot/readiness detail. Running Pi failures also append one precise alert and blocked/recovered lifecycle edges through existing condition tracking; cancellation is silent and healthy installs emit nothing. Root, files and source stay in private context; no success/adoption history record.

**Rejected:** preview/refetch ([PR 224](https://github.com/schani/pi-orb/pull/224)): duplicate fetching, a mutable gap and broader delivery machinery. The [GitHub study](https://files---pi-orb-issuer-1077475695242.us-central1.run.app/s/f80c5983-861b-49b6-9bb1-6683386edf7c/design/github-owner-skills/index.html) records the selected pinned snapshot and proposal 3 draft-row Source. Validation: `docs/testing.md`; remaining qualification: `TODO.md`.

## Five configuration proposals (2026-10-26)

Interactive study: [hosted](https://files---pi-orb-issuer-1077475695242.us-central1.run.app/s/6e16dc75-2326-4f5a-bbfd-853e5ce5fcd0/design/global-skills-secrets/index.html). It links a snapshot of `apps/web/src/styles.css` and reuses captured production markup: dashboard totals/masonry columns, the 560px Settings/Config frame and tabs, the MCP workbench disclosure and the Secrets pane. State is in memory only.

1. **Settings tabs.** The dashboard gear's Settings gains Skills and Secrets tabs (Instructions · Skills · Secrets · Git · Claude). Skills reuse the MCP disclosure, one row per skill expanding to its `SKILL.md`; Secrets is the project Secrets pane unchanged. Smallest; long skills are edited in 560px and five tabs are tight on a phone.
2. **Inherited in project Config.** No owner-level entry point. Each project's Config shows the effective set: own secrets, then "all projects" secrets, struck through where overridden. The secret form gains a scope choice; a Skills tab lists owner skills. Shows exactly what an orb receives; repeats the scope confusion rejected for personal instructions.
3. **All-projects box.** A permanent first board box built like a project column: skills and secrets with + per group; rows open the 560px sheet. Always-visible inventory; costs a column and resembles a project.
4. **Totals counters.** `N skills` and `N secrets` totals open dedicated sheets; Skills uses a wider list | editor sheet. Mixes configuration counts with fleet state; phone totals grow to three rows.
5. **All-projects page.** A layers icon beside Usage opens an addressable page with a 236px index and full-height editor; each skill has a URL, and missing skills show a resource-specific message. Most writing room; adds a route and leaves the board.

Browser smoke checks (2026-10-26, Chromium, 1440px and 390px): no horizontal overflow; frontmatter validation, failed-save draft retention and save receipt; secret add; project-scope override; sheet open/close; missing-skill page.
