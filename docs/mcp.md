## Project configuration and authority

**Dependency security update (2026-10-07; not deployed):** control-plane OAuth and description probes use `@modelcontextprotocol/client@2.2.0`, which fixes OAuth credential forwarding to an MCP-server-selected authorization server ([GHSA-6qxp-vccf-f47h](https://github.com/advisories/GHSA-6qxp-vccf-f47h)). Pi uses its native MCP transport; Claude's OAuth bridge uses `@modelcontextprotocol/sdk@1.32.0`.

A project owns its revisioned catalog (at most 20 servers, 16 headers/server), not an account-wide set. Its Config → MCPs tab saves name, bounded description, HTTPS endpoint and OAuth or static secret references; Secrets owns key values. Custom headers remain supported through the API, although the narrow editor refuses to alter configurations it cannot represent. Presets cover PostHog bearer auth and Cloudflare/Datadog US5 OAuth. Catalog publication and secret removal share the project row lock: referenced secrets cannot be deleted; replacing a secret is allowed. Browser configuration changes apply on the next runtime start; OAuth reauthorization for an existing connection works without restarting. The short name/description inventory is appended to the agent context without connecting to servers or claiming they are healthy; the shared environment prompt directs setup to the project gear.

`GET /api/v1/projects/:projectId/mcp` returns `{revision, servers}`; `PUT` replaces the catalog with an expected revision. `GET /runtime/v1/mcp` uses the orb incarnation bearer and derives its project. Runtime boot resolves static bindings against its project-secret snapshot; missing authoritative snapshots fail readiness, not become an empty catalog. Control-plane description inspection is restricted to public HTTPS with socket-time DNS checks, disabled redirects, and no userinfo or fragments. The orb may connect to an approved private endpoint: allowing project code to reach one does not grant the control plane a private-network fetch primitive. No live catalog push, shared MCP session, gateway or fleet connection supervisor is introduced.

OAuth catalog entries carry immutable project/URL-bound `oauth: {id}`. Browser `GET .../mcp/:id/oauth` reports `connected | pending | auth_required`; `POST .../oauth/connect` returns `{url}` and `POST .../oauth/disconnect` returns `{status:"auth_required"}`. The stable `${PI_ORB_APP_ORIGIN}/api/v1/mcp/oauth/callback` exchanges authorization codes in the control plane and returns to the project's MCP tab. State, browser nonce, PKCE and single-use exchange ownership are fenced and time-limited. OAuth tokens, client secrets and verifiers belong to immutable control-plane secret versions, never project-secret snapshots, repository files, guest OAuth storage, browser reads or history. Catalog removal/auth-mode or URL replacement retires the grant; an old callback/refresh cannot resurrect it. Transactional `mcp_oauth_events` record safe consent, invalidation and refresh edges; `mcp_oauth_garbage` owns exact-version cleanup. The broker reuses leased refresh and generation CAS; refresh accepted upstream before a lost response is not recoverably atomic and can require new consent. `POST /runtime/v1/mcp/:id/token` accepts `{url, rejectedGeneration?}` and returns `{accessToken, expiresAt, generation}` after checking incarnation and current catalog ownership. Previously issued access tokens survive disconnect until expiry/provider revocation. This route does not expand the global model/GitHub broker capability enum.

Initial registration uses advertised dynamic client registration and authorization code + S256 PKCE. Discovery/registration/token requests use public HTTPS, socket-time DNS validation, disabled redirects, ten-second deadline and 1 MiB response cap. Callback headers disable storage/referrers; callback URLs must not reach ingress logs. Migration 018 and deployed logging exclusion are described in `docs/credentials.md` and `docs/postmortems/2026-09-11-release-logging-exclusion-iam.md`. Migration 026 adds safe `mcp_oauth_events.detail`: closed diagnostics (`invalid_grant`, `invalid_client`, `missing_refresh_token`, `unusable_refresh_response`) and bounded lifetime/rotation metadata, never remote bodies or credentials (`docs/postmortems/2026-09-26-provider-auth-failures.md`).

## Native Pi boundary

Pi owns MCP tool-schema validation; pi-orb uses TypeBox for its own protocol and configuration schemas.

`DefaultResourceLoader` composes a named native `createMcpExtension` with ordinary user/project extension discovery. `loadConfig` uses only the approved boot catalog, sets native exposure to codemode, and uses a dummy Authorization placeholder required by native configuration; it is **never sent on the wire**. `createTransport` permits only a matching approved server and constructs the SDK's public `StreamableHttpTransport` from the same package copy as native Pi (avoiding duplicate-module exception-identity failure). A narrow Pi 0.99.1 patch reexports that transport, adds `onServerChange` and `retryConnectionOnPrompt`, and rebases the custom-triggered-turn preparation and sanitized Codex diagnostic patches. No default guest OAuth provider is installed: an inert credentials store prevents `mcp-auth` persistence or guest consent. A tokenless native auth-provider hook enables native bounded retries without taking credential ownership.

**Decision (2026-09-30; locally implemented and isolated-live qualified):** retry initially failed OAuth discovery on the next prompt when its safe diagnostic identifies missing authorization, broker unavailability or persistent 401. Native `waitForOpening()` settles a prior failed attempt before `getClient()` owns singleflight opening, shutdown fencing and discovery; its startup wait stays bounded. Healthy connections, static bindings and unrelated upstream failures are not retried by this hook. There is no timer, guest token store or tool-call replay. This host-specific eligibility hook is necessary because browser consent changes the broker, not Pi's inert guest credential store; app message paths do not dispatch native slash commands.

The custom fetch resolves approved static headers and brokered access tokens **per HTTP request**, including GET/POST on a live MCP session. It binds the request AbortSignal, rejects redirects, discards remote error bodies and retains only the opaque `WWW-Authenticate` challenge for native parsing. Never log request/response headers, challenge text, URLs with credentials or remote bodies. Native 401, challenged 403 and invalid-session 404 recovery may retry once; ordinary 403 is not a consent escalation. Timeout or an accepted write whose response is lost must **not** automatically replay. Failed upstream connections do not prevent unrelated coding. `logPath: "/dev/null"` suppresses native persistent unsanitized server-notification logs.

Each Pi session owns independent native MCP clients and credential cache. Children receive only explicit approved native factories; a child-profile tool allowlist controls direct tools **and nested codemode calls**. **Decision (2026-10-01, after live qualification):** the built-in general-purpose child must have the project's approved MCP access. An omitted child tool list means unrestricted access to its approved child resources, including asynchronously discovered native MCP tools; it must not become a finite built-in-only list. Explicit tool lists remain authoritative, including a custom profile named `general-purpose`. This uses Pi's tool policy, not a copied root tool snapshot or a second connection manager. Implemented and validated 2026-10-02: actual vendor-child tests cover delayed discovery, successful MCP through codemode, explicit-profile direct/nested denial and empty catalogs; the full 248-case browser suite verifies default delegation and authenticated calls. This later policy change is not part of the earlier live-image/context archive (`docs/testing.md`). A narrow `patch-package` patch on the installed `@gotgenes/pi-subagents@21.7.0-orb.8` adds codemode to explicitly supplied child tools, binds the selected allowlist before inference and rejects unapproved reserved MCP namespaces. The model-selection artifact retains this patch (`docs/subagents.md`). Root shutdown drains child client execution and closes child sessions before the root connection; children never own the root's client. Cancelling a client request cannot undo remote work already accepted. Pi native prompts remain unsupported: the 2026-09-29 live GlideOS catalog (Cloudflare, Datadog US5, PostHog) returned zero prompts on all three; the user accepted this cutover scope. That inventory does not prove historical usage or other projects' inventory. Native tools and resources remain external, untrusted data; resource URIs go through the selected MCP server, not an arbitrary local or HTTP reader. MCP Apps, sampling and elicitation do not acquire browser interaction automatically.

## Visibility and replication

`onServerChange` is the sole state-edge publisher. Per-server failure, needs-auth, disconnect and recovery edges are coalesced and appended to the root Pi session as `pi-orb:mcp-status` **custom entries**, not `custom_message` (which could interleave between a call and its result). Entries retain the native session ID, root/child source, safe diagnostic code and optional numeric HTTP status; the typed history mapper emits safe visible text, labeling child failures. Broker `auth_required` and persistent upstream 401 failures become `needs-auth` without depending on error wording. No raw upstream error string is stored. Initial healthy connection and repeated levels are silent. `pi-orb:mcp-config` adoption entries retain revisions and names, not secrets. Native tool results and history replication remain the normal output path. A hidden native `codemode-store` entry remains one history record and is not promoted into invented tool calls.

The codemode parent `tool_result` contains a bounded typed nested-call summary. Its disclosure shows child tool inputs, status, sanitized error, duration and available summary; it does **not** manufacture full child results. Incomplete or filtered summaries state that limit explicitly. Transient nested events are excluded from root live-tools projection; only committed parent summary is rendered. This keeps live and replicated views consistent without a separate child-history endpoint (`docs/pi-adapter.md`, `docs/web-ui.md`).
