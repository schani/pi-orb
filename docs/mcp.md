# Remote MCP

Projects configure remote MCP servers. Pi's MCP tools run centrally as scoped Durable callables with request-time broker credentials; native Claude uses a query-owned bridge on its host (`docs/claude.md`). Project configuration and OAuth authority stay in the control plane; neither harness holds refresh tokens.

**SDKs.** Central Pi execution, control-plane OAuth, status checks and description probes use `@modelcontextprotocol/client` 2.4.0 with exact `@modelcontextprotocol/core` 2.4.0 (`apps/control-plane/package.json`). Claude's OAuth bridge uses `@modelcontextprotocol/sdk` 1.32.2 in the runtime. Issuer-bound credential protection ([GHSA-6qxp-vccf-f47h](https://github.com/advisories/GHSA-6qxp-vccf-f47h)) is required: mismatched stamped credentials must be rejected before any token request.

## Project configuration

- A project owns a revisioned catalog: at most 20 servers, 16 headers per server; no account-wide set. Config → MCPs saves name, bounded description, HTTPS endpoint and OAuth or static secret references; Secrets owns values. Custom headers are supported through the API; the editor refuses to alter configurations it cannot represent. Presets: PostHog bearer, Cloudflare and Datadog US5 OAuth.
- Catalog publication and secret removal share the project row lock: referenced secrets cannot be deleted; replacement is allowed.
- Project-secret exposure model: an MCP API key is an ordinary project secret, readable by the orb. Config stores secret references; headers resolve in memory.
- `GET /api/v1/projects/:projectId/mcp` returns `{revision, servers}` with secret references, never resolved headers. `PUT` replaces the catalog at the expected revision: deletion-fenced, stale or missing-secret-reference writes 409, missing project 404, malformed or duplicate 400, outage 503. `POST .../mcp/describe` inspects one config over authenticated public HTTPS with project secrets and returns a bounded `{description}`; no persistence, no OAuth. Successes are non-cacheable. `GET /runtime/v1/mcp` uses the incarnation bearer, derives the project and returns secret references, not resolved keys. Boot resolves static bindings against the project-secret snapshot; a missing snapshot fails readiness rather than yielding an empty catalog.
- Catalog changes apply at the next runtime start; OAuth reauthorization works without restart. No live catalog push, shared MCP session, gateway or connection supervisor.
- Control-plane description inspection allows only public HTTPS with socket-time DNS checks, disabled redirects, no userinfo or fragments. Orbs may reach approved private endpoints; that never gives the control plane a private-network fetch primitive.

## OAuth

- OAuth entries carry immutable project/URL-bound `oauth: {id}`. `GET .../mcp/:id/oauth` reports `connected | pending | auth_required`; `POST .../oauth/connect` returns `{url}`; `POST .../oauth/disconnect` returns `{status:"auth_required"}`. The stable `${PI_ORB_APP_ORIGIN}/api/v1/mcp/oauth/callback` exchanges codes in the control plane and returns to `/projects/:projectId/mcp`; validation failures go to a clean error page (`/mcp/oauth/failed`). An app session expiring mid-ceremony fails visibly; the user restarts the flow.
- State, browser nonce, PKCE and single-use exchange ownership are fenced and time-limited. Tokens, client secrets and verifiers live in immutable control-plane secret versions, never project-secret snapshots, repository files, guest storage, browser reads or history. Removing the entry or changing auth mode/URL retires the grant; old callbacks and refreshes cannot resurrect it.
- Registration uses advertised dynamic client registration and authorization code + S256 PKCE. Discovery, registration and token requests use public HTTPS, socket-time DNS validation, disabled redirects, a 10 s deadline and a 1 MiB response cap. Callback responses disable storage and referrers; callback URLs must not reach ingress logs (`docs/credentials.md`, `docs/postmortems/2026-09-11-release-logging-exclusion-iam.md`).
- Direct exchange and refresh use the persisted issuer, token endpoint and resource without rediscovery; changed discovery yields a typed, sanitized issuer rejection with zero token requests.
- The `mcp-oauth` secret namespace holds PKCE/client context and tokens behind exact-version pointers (migration 018). Version retirement is queued transactionally and a collector destroys retired versions; project deletion also enumerates unpublished residue after quarantine.
- `mcp_oauth_events` records consent, invalidation and refresh edges transactionally; `detail` (migration 026) holds closed diagnostics (`invalid_grant`, `invalid_client`, `missing_refresh_token`, `unusable_refresh_response`) and bounded lifetime/rotation metadata, never remote bodies or credentials (`docs/postmortems/2026-09-26-provider-auth-failures.md`). `mcp_oauth_garbage` owns exact-version cleanup.
- The broker reuses leased refresh and generation CAS. A refresh accepted upstream before a lost response cannot be recovered atomically and may need new consent. `POST /runtime/v1/mcp/:id/token` accepts `{url, rejectedGeneration?}` and returns `{accessToken, expiresAt, generation}` after checking incarnation and catalog ownership. Only access tokens enter harness memory; request-time resolution refreshes an existing connection without changing the boot catalog. Repair never restarts an orb or replays the failed MCP operation. Issued access tokens survive disconnect until expiry or provider revocation. Static-key revocation is the provider's job.
- **iOS standalone consent.** In the installed PWA, Connect/Reconnect opens the project MCP settings page in Safari before calling `connect` (Add & connect saves first); the user clicks Connect again there so nonce cookie and callback share one cookie jar. The PWA never starts consent for this handoff; focus return or visible `visibilitychange` refreshes status. Route tests reject a missing or foreign nonce. Rejected: handing a PWA-started consent URL to Safari (separate cookie jars break nonce binding), query/GET-triggered consent (CSRF surface), a bridge route.
- **Grant stored.** The workbench renders API `connected` as **grant stored**: a persisted OAuth secret version exists. Neither that nor successful discovery proves usable upstream authorization. Arbitrary tool errors never invalidate grants or replay calls.

## Status check

`GET /api/v1/projects/:projectId/mcp/status` (owner-scoped, non-cacheable) checks the saved catalog from the control plane with saved secret bindings and the OAuth broker. It initializes each server and lists tools only when advertised; it invokes no tool and probes no resources/prompts. Up to 20 checks run concurrently, each with one 10 s network deadline for initialization plus discovery. Cleanup aborts transport/SSE and destroys the socket dispatcher without awaiting remote session deletion. The browser allows 75 s.

Response `{revision, servers:[{name, status, diagnostic?}]}`:

| status / diagnostic | meaning |
|---|---|
| `available` | initialized and, if advertised, tools listed; not proof of upstream authorization |
| `unavailable` / `connection_failed` | this check failed (HTTP 403 included) |
| `needs-auth` / `auth_required` | broker has no consent, or HTTP 401; no grant invalidation or replay |
| `unknown` / `credentials_unavailable` | credential store or broker failed |
| `unknown` / `invalid_binding` | missing/invalid headers, or endpoint rejected by public-HTTPS/DNS policy (approved private endpoints are unreachable from here) |

No URL, config, header, token, tool list or raw error in responses. Checks run on settings open, focus return and manual refresh; no polling, persisted health, runtime reads or compute start. Rejected: per-orb caches and harness observers (different question, lifecycle coupling).

## Config UI

Config → MCPs is a workbench of chat-style ▸/▾ disclosures, one expanded server at a time. The summary is name plus authorization state (**grant stored**, above); editing and Connect/Reconnect/Disconnect/Remove live inside. Forms stay mounted when collapsed or switching tabs. No restart notice.

- **Add** opens a compact ledger: Name, HTTPS Endpoint, then OAuth or Bearer token. Bearer is a dropdown of project-secret names, refreshed on returning from Secrets or focusing the picker; an unavailable saved selection is shown but cannot be submitted. Values are entered only in Secrets. Presets are subordinate links (Cloudflare and Datadog US5 → OAuth; PostHog → `POSTHOG_KEY`). Creation asks no description: OAuth gets a bounded name-based one, bearer uses authenticated `describe`. Descriptions are directly editable; no Advanced/JSON editor. Existing bearer entries save without successful reinspection; new ones require it. Unrepresentable custom-header configs stay intact and say this editor cannot modify them.
- **Saving** keeps the OAuth ID when the endpoint is unchanged; endpoint or auth-mode changes do not reuse the grant. Add & connect saves first, then starts consent; if initiation fails, the saved row opens with an explicit saved-but-not-authorized error and retry creates no duplicate. Conflicts and failed saves keep drafts. Async publication/navigation is fenced to the component lifetime; status reads are fenced against newer reads and mutation completion.
- **Inline health** sits beside the authorization state. One project-scoped batch status read on tab entry, window focus or the icon-only refresh; no polling or browser persistence. Pending is visible; one component-scoped flight prevents overlap and a superseded batch finishes before the latest context is checked; refresh is disabled while checking or saving. HTTP failures, missing rows and catalog-revision mismatches show unknown; failed reads add a retryable inline error. Closed diagnostics appear in the health title, never raw errors, URLs or HTTP details. Project/revision keys reject stale results; refresh preserves disclosure, drafts, OAuth actions and focus.
- OAuth + bearer only: no popular MCP requiring other headers lacks an OAuth/bearer alternative (Datadog has OAuth; Context7 and Grafana accept bearer). Dropping extra headers also drops non-auth context headers (e.g. PostHog project pinning); the backend catalog/header contract stays general.

## Central Pi

- `McpTools` uses official clients behind typed scoped endpoints. Discovery registers canonical `mcp__server__tool` names (no aliases), original JSON Schemas and server instructions/resources in the callable catalog; models reach them only through code-mode (`docs/pi.md`). Resource URIs are interpreted by the selected server, not as filesystem or HTTP paths. Resource/template discovery is lazy; tool discovery never eagerly lists resources.
- **Batch validation.** Each endpoint's complete tool batch is validated before registration: raw names and native code-mode identifiers must be unique within the batch and against the shared catalog, including hidden entries. A later conflicting endpoint is rejected through the sanitized unavailable status; the incumbent and unrelated endpoints continue. Exact re-registration after transient failure is allowed; changed aliases cannot take identifiers held by cached callables. No automatic renaming.
- **Arguments.** Original arguments are checked against the raw server schema (non-coercing TypeBox `Check`) before native coercion, preparation hooks, authorization, per-call credentials or effects. Explicit null stays null; only omitted arguments default to `{}`. Invalid input gets a fixed sanitized rejection through the Harness-required throw; no input or remote text reaches model output. On native `invalid_arguments`, only missing top-level required names are derived from the catalog (quoted, ≤64 characters each, ≤16 names, ≤1,024 characters total). Check the authenticated live schema before blaming credentials for argument rejection (`docs/postmortems/2026-10-21-posthog-exec-required-context.md`).
- **Declarations.** When oversized property descriptions exhaust the declaration budget: tag-free attempt, then no descriptions, then `unknown`. Types, requiredness, references and caps are unchanged.
- **Results.** Validation follows the negotiated protocol: modern `structuredContent` accepts any JSON value, including arrays and null; legacy accepts only objects. Invalid responses fail sanitized; no permissive codec. Full raw schemas, deferred metadata and complete result envelopes stay intact.
- **Discovery.** Starts automatically after root/projection initialization and final admission, just before Harness resume, as one context-owned background job publishing each server independently; startup and code-mode preflight never await it. The resource lease owns it: revocation aborts it before Harness shutdown, and resource close joins discovery and notifications even when cleanup fails. Discovery is serial and failure-tolerant; the SDK's 30 s timeout is per JSON-RPC request. Configured namespaces exist immediately with pending descriptions. The `mcp_status` description lists each configured server's name, cached status, namespace and description, so native search finds a provider before its tools arrive. `mcp_status({})` returns cached progress at once and starts or shares a background retry of failed servers; cancelling its script does not cancel the job. Each endpoint publication rebuilds the registry, and the next script's preflight makes new tools callable. Rejected: discovery only via `mcp_status` (hides configured tools, depends on model choice) (`docs/postmortems/2026-10-22-mcp-startup-deadline.md`).
- **Calls.** Each invocation owns an official client and cancellable transport, resolves credentials afresh and joins cleanup. Cleanup aborts outstanding POSTs, attempts legacy session termination (1 s best effort, independent of caller cancellation but rechecking owner, catalog, secrets and lease), then joins client close. `versionNegotiation: { mode: "auto" }`: [`server/discover`](https://modelcontextprotocol.io/specification/2026-07-28/server/discover) negotiates modern MCP (`2026-07-28`, no protocol sessions or GET stream) and falls back to legacy initialization. Version-negotiation retries are not business-call replay. HTTP 404 never reinitializes or replays; only JSON-RPC `-32601` permits an empty-template fallback. Calls supply their cached discovered definition (no automatic `HEADER_MISMATCH` refetch) and set `inputRequired: { autoFulfill: false }`. Replay follows native safety/admission rules; cancellation cannot undo accepted remote work.
- **Target scope.** A switch acknowledgment or read in another legacy transport session cannot establish a mutation's target (`docs/postmortems/2026-11-06-posthog-project-selection.md`).
- **Transport security.** Fetch enforces `redirect: "error"` after caller options, so cross-origin 307/308 never forwards project-secret headers. Request-time broker fetch keeps generation fencing and bounded token recovery on HTTP 401; HTTP 403 fails without OAuth recovery. Non-success bodies are sanitized; headers, tokens, challenge text and credential-bearing URLs are never persisted. MCP tools and resources are untrusted data; sampling, elicitation and MCP Apps never acquire browser interaction. Native prompts are not supported.
- **Visibility.** Discovery failures emit `durable.mcp_unavailable` lifecycle events with server, authoritative `needs-auth|unavailable`, active phase, phase elapsed time, abort status, allowlisted SDK category and HTTP status/timeout where known. Discovery and invocation failure/recovery share one publisher that appends native `orb.alert` entries without model input. The `mcp-status` system section refreshes before each root/child request, including requests prepared before discovery finished (`docs/agent-context.md`). Alert-publication failure records `durable.mcp_alert_failed` and does not stop discovery. Healthy connections and repeated levels are silent.
- The code-mode parent result carries a bounded nested-call summary (inputs, status, sanitized error, duration); it never manufactures full child results, and incomplete summaries say so. Rendering: `docs/web-ui.md`.

## Rejected

- pi-orb-owned `mcp_search`/`mcp_call`/`mcp_read` tools and connection manager: native search, deferred tools and code-mode own discovery and context budget.
- Third-party Pi MCP adapters: guest keyring/OAuth ownership or credential persistence.
- A gateway hiding keys from project code that is already authorized to read them.
- In-orb setup proposals; setup happens through the project gear.
