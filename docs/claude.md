# Claude harness

Native Claude Code runs through the Claude Agent SDK on the orb's execution host, co-located with the workspace. SDK and CLI are pinned together (`@anthropic-ai/claude-agent-sdk` / `@anthropic-ai/claude-code`, matching versions) in immutable image inputs; no startup npm install. Pi runs centrally (`docs/pi.md`).

## Harness selection and topology

- Each orb has one immutable `harness: pi | claude`, chosen at creation; Pi is the default. No live switch, session migration or cross-harness history conversion. Selection propagates through creation, launch storage and the runtime boot protocol; `pi-orb spawn` inherits the caller's harness inside its fenced creation transaction. AgentPlane dispatches health, inbox, stop and replication by the persisted harness.
- The SDK/harness runs on the orb host. Rejected: a trusted harness worker separate from the workspace; native tools, hooks, skills, filesystem context and session ownership do not relocate through tool aliases or remote MCP. Central Claude in the control plane is rejected for the same reason.
- Native Claude implements the narrow `OrbAgent` port behind runtime HTTP; the browser reaches it through the control plane's live proxy, and history replicates by pull (`docs/history.md`). Controllers never call SDK, disk or model clients directly. Fallible boundaries return typed `Result`/`ResultAsync`; SDK calls, iterator failures and process/disk rejections are caught at the adapter.
- The SDK runs native Claude Code, not a raw model loop: `query()` with `AsyncIterable` prompt input, one retained native root session per orb with explicit `sessionId`/`resume`, native tools. No terminal scraping.
- Retained native files on the orb filesystem are the only resume authority. The normalized product replica is display state and cannot hydrate native resume. No `SessionStore`: its mirroring is best effort (a failed batch is dropped while inference continues) and resumed temporary files are deleted at session end.

## Authentication

One owner-level Claude subscription connection serves all of that owner's orbs; no per-orb login and no user CLI step. Credential storage, the runtime grant route and the accepted long-lived guest bearer exception: `docs/credentials.md`.

- **Ceremony.** The owner clicks Connect in Settings → Claude. A trusted auth-only backend helper runs pinned `claude setup-token` under a PTY (1024 columns, so the authorization URL is not wrapped and truncated) with an isolated home and no checkout. Pi-orb shows the native authorization link; the owner consents at Anthropic and pastes the completion code into pi-orb. The helper sends bracketed paste, waits for the masked redraw, then sends Enter separately; text plus Enter in one chunk is not native submission. The printed token goes directly into the owner's secret slot; raw PTY output, token and credential files never reach browser or logs.
- After a code POST succeeds, the dialog shows **Completing connection…** until polling sees publication or failure; acceptance is not authentication success. The backend clears the challenge on code acceptance and rejects duplicates. A fresh dialog reading `connecting` without a challenge shows **Connecting…**. Recognized native validation/exchange failures surface immediately and end the helper. Sanitized lifecycle edges distinguish code acceptance, native input completion and failure stage/reason (`docs/postmortems/2026-10-04-claude-auth-completion-input.md`).
- The SDK has no login API. No custom OAuth client, token exchange or fake renewable `StoredCredential`. Native `/login` is rejected: it stores guest-readable refresh credentials and needs terminal access before readiness. Rejected: a credential-injecting gateway; gateway credential variables or `apiKeyHelper` replace subscription login, losing subscription limits and billing.
- **Sign-in UI.** Settings → Claude reads status only while that tab is active. Connect/Reconnect starts sign-in and opens Anthropic consent in one click; Disconnect clears the saved connection. A `claude_subscription_login` challenge on an orb opens the same flow; viewers see only owner-login-required. The trusted click reserves a tab showing only "Connecting" and removes its opener before reading status; only an allowlisted HTTPS Anthropic challenge navigates it, once. Blocked, closed or unavailable tabs show a typed failure plus the direct consent link. In the iOS home-screen app the validated URL goes straight to Safari via `x-safari-` without a reserved tab. The dialog stays open for the completion code; returning keeps Claude selected and focuses the code input. Challenges and codes live only in component memory; the code clears on submit, visibility change and close. One non-overlapping status poll runs while connecting and visible (a reserved tab still awaiting its URL also polls while hidden). Mutations fence and abort earlier reads; hide/close/unmount fence late results; closing disposes unused tab reservations without cancelling the ceremony. Failed reads stop polling and offer Retry. Browser calls never choose an owner or orb.
- **Child environment.** Only the SDK subprocess receives `CLAUDE_CODE_OAUTH_TOKEN` and `CLAUDE_CONFIG_DIR`. It strips only variables that can replace the subscription credential: `ANTHROPIC_*`, `CLAUDE_CODE_*`, `CLAUDE_CONFIG_DIR`, `BASH_ENV`, `ENV`; native settings also blank `apiKeyHelper` and the provider-selection variables. Cloud credentials (`AWS_*`, `GOOGLE_APPLICATION_CREDENTIALS`, `CLOUD_ML_*`) stay: they select no provider without `CLAUDE_CODE_USE_*`, and stripping them once silently broke workload identity in hooks and Bash. `verifyClaudeAccount` blocks inference on any non-first-party account. Successful validation stores only auth source and grant generation in the private session pointer. Rejection, expiry and replacement are visible readiness failures.
- A Claude-only owner needs no Codex connection. Luna naming and summaries are skipped when Codex is unconfigured; no API-billed Anthropic auxiliary calls.

## Native settings, permissions and context

- Query options: `tools` and `systemPrompt` use the `claude_code` preset; `settingSources: ["user", "project", "local"]`; `skills: "all"`; `permissionMode: "bypassPermissions"` (the existing trusted unrestricted policy). No `Options.agents` dictionary. Native settings govern CLAUDE.md/AGENTS.md selection, imports and directory discovery; repository files are never rewritten. What the system-prompt append contains and when it is adopted: `docs/agent-context.md`.
- `AskUserQuestion` and `canUseTool` have no product UI. Not implemented: visibly declining unsupported asks with a persisted diagnostic.
- **Root-only delegation.** Only the root may call native `Agent`. A `PreToolUse` hook denies every `Agent` call with nonempty `agent_id` (`permissionDecision: "deny"`, reason `Delegate from the root; complete this assignment directly.`). Root delegation, including background and custom agents, is unchanged. The hook persists hidden `claude.nested_delegation_denied` (session/query/operation/agent/tool-use IDs) before returning; persistence failure still denies and fails health; stale-query or unadmitted callbacks deny without an edge. Rationale: headless native sessions (piped stdout) cannot deliver descendant completions to a stopped nested owner, and `background: true` agent definitions override `run_in_background: false`, so foregrounding cannot be enforced (`docs/postmortems/2026-10-06-claude-nested-owner-continuation.md`). Probe: `scripts/claude-sdk-contract/nested-continuation.mjs`.

## Query lifecycle

The query process rotates between completed turns: a permanently open query cannot establish an idle fence through public APIs. The initial account/catalog probe and every rotation wait for owned work, supervised native exit, stdout EOF, public iteration, tracked hooks, MCP request cleanup and the fsynced, published native history. Late native inference during rotation is a failed operation, not an invented completed turn. Unexpected SDK EOF is a visible failure, not a ready dead query. Credential source validation precedes prompt admission, and each new query fetches the current owner grant.

- **Supervision contract.** Every `ClaudeQueryProcess` (including test factories) supplies `exited: Promise<void>`, `stdoutEnded: Promise<Result<void, {message}>>` and `requestShutdown(): Result<void, {message}>`. Completing the input `AsyncIterable` lets the SDK end stdin gracefully. No direct stdin close, killing-as-success or timeout-to-idle; a missing edge retains ownership. The SDK's `close()` can end its public queue before the transport reaches EOF, so iterator completion alone is not drain proof.
- **Admission.** Queries require `queryReady`, not merely an assigned SDK. Metadata/model/settings failures fail closed; initialization and settings guards survive until all drain barriers above. SDK/MCP cleanup follows them. Late root work or unresolved child/task ownership keeps busy/child guards, fails health and makes settings read-only. Failed cleanup or rotation persists a sanitized reason and cannot publish a completed terminal.
- **Native hooks.** `hook_started`/`hook_response` markers are matched by `hook_id`; a matching response (including `cancelled`) releases only that hook. Setup and SessionStart hooks may run during initialization and shutdown. Markers unmatched after all drain barriers fail attach/settings/rotation/interruption closed and persist only the pending count. Rotation makes SessionStart/SessionEnd hooks run per query.
- **Stream fairness.** The consumer yields with `setImmediate` before every SDK message, then fences query identity; only `stream_event` skips the trailing history flush.
- **Zero-turn results.** `SDKResultMessage` can acknowledge a command without inference (`num_turns: 0`, `stop_reason: null`); `queued_turn_count` excludes system entries. A successful zero-turn result without singular or plural input UUIDs does not change root completion. The synchronous operation claim holds initial input during startup; pending steering and queued turns still restart the root. An acknowledgment cannot resurrect a completed root held by hooks or children (`docs/postmortems/2026-11-05-claude-query-rotation-93add73b.md`).
- **Rate limit.** A terminal root result with `subtype: success`, `is_error: true`, `api_error_status: 429` fails health as `claude_rate_limit` before releasing root/handoff ownership, when nothing is pending or queued, health is ready, and no close, manual compaction or Abort is in progress. It requests best-effort `interrupt({ cancelQueued: true })` and starts supervised shutdown without awaiting it; cancellation rejection records `claude.cleanup_failed`. The failed-runtime lifecycle stops the compute; the user waits for quota reset and restarts. No automatic retry (`docs/postmortems/2026-10-24-claude-terminal-failure.md`).
- **Shutdown diagnostics.** The first close synchronously snapshots caller, outcome, result metadata, drain holds and nine ownership groups (full counts; four IDs each, ≤64 ASCII identifier characters), <4 KiB, not replaceable by later results. Abort is `operation_drain`. While closing, it records requesting status, root assistant/tool-use IDs and allowlisted tool kinds, task start/notification IDs and status, result metadata and root tool-result IDs/errors (forwarded child frames excluded). The sequence resets at query initialization. The whole `shutdownDiagnostics` JSON is ≤8 KiB with ≤32 edges, evicting oldest and counting drops; invalid or clipped IDs are counted. No prompts, commands, arguments, output or SDK text. Published only in `claude.rotation_failed` overflow (`docs/postmortems/2026-11-04-claude-query-rotation-1f315657.md`).

## Ownership and handoffs

Aggregate busy comes from owned query, subprocess, child, task, handoff and cleanup holds, not from root results. Native signals that do not prove idleness: `system/status` (`compacting | requesting | null`), `background_tasks_changed` inventories (ordering against root bookends is unspecified; there is no `Query.getBackgroundTasks()`), Stop/StopFailure hooks, `interrupt()`/`stopTask()` receipts (acceptance, not cleanup) and `Query.close()` (destructive, not awaited). Detached dev servers intentionally do not block idle-stop. Native pre-inference fencing of SDK-originated starts is unproven (question 73). Uncertain-worker compute recovery: `docs/lifecycle.md`.

- **Task handoff.** A background task terminal requires a subsequent root `requesting` edge followed by a nonzero-turn result. Results from inference already in flight at notification time and zero-turn acknowledgments cannot finish it. Handoffs snapshot at `requesting`; a task finishing during that inference stays owned until a later pair. Live and durable ownership retire the same IDs. No grace timer or replay. Hidden `claude.handoff_result` records completed, pending and awaiting handoffs; `claude.rotation_failed.rootWork` records the first late signal (`docs/postmortems/2026-10-13-claude-query-rotation.md`).
- **Closing-task handoff.** When `task_started` and its terminal notification both arrive during one closing query, the atomic session journal keeps exact task/start/notification IDs, session, query, operation, terminal status and compute lifetime (`handoffTerminals` beside `pendingHandoffs`). After supervised cleanup and final publication, one visible `claude.handoff_interrupted` precedes releasing only that handoff; the operation retires as aborted. Same-compute recovery repeats this idempotently. Child admissions and background inventories stay independent ownership.
- **Workflow children.** A complete successful native `result` alone proves its child terminal, after awaited runner cleanup; `started`, failed and cancelled records never release ownership. The private reader scopes journals to the validated root's immediate `subagents/workflows/wf_*/journal.jsonl` (run/agent IDs ≤128 characters; keys `v` + 1–8 digits + 64 hex). Payloads never leave the adapter; malformed evidence and I/O/fsync failures are typed errors, with fsync before proof. One deduplicated result-identity list supplies admission baselines and reconciliation; preexisting tokens and duplicate-ID admissions are excluded. History/replication snapshots are the only reconciliation wakeup; no timer. Release order: durable idempotent `claude.workflow_child_terminal` → ownership save → live release; failures keep ownership and fail health (`docs/postmortems/2026-10-15-claude-stale-subagent-ownership.md`).
- **Continuation diagnostics.** After a nested-delegation denial, or a zero-turn acknowledgment suppressing completion of an active root without owned work, hidden `claude.continuation.*` edges record root results (subtype, IDs, ownership counts), task bookends, changed inventories (IDs/ambient only), changed closing decisions and drain start/outcome. Unchanged levels and unaffected queries publish nothing; at most 32 edges plus a drain summary with the suppressed count. No content.
- Rejected: clearing ownership on root result, inventory absence, SubagentStop, process exit or EOF (none proves escaped workers ended); clearing a proved terminal's handoff without a durable interruption (silently discards its continuation).
- **Roster classification.** Optional roster `kind: "shell"` marks shells. Agents are admitted through `SubagentStart` or native `task_type: "local_agent"`, shells only through `task_type: "local_bash"`; other or untyped tasks stay owned but unclassified; ambient tasks are excluded. Learned types survive on extant task edges and handoffs keep their category regardless of inventory/bookend order. Classification is transient; saved ownership IDs and replicated outcomes keep lifecycle evidence.
- After proved execution-lifetime loss, startup publishes one idempotent `claude.children_interrupted` keyed by the recovery episode before clearing ownership; completed native results and durable inbox receipts stay. Old child work is never replayed.

## Input and steering

- Human input uses `priority: "now"` with `origin: { kind: "human" }`: native Claude backgrounds eligible work and consumes it within the current turn, or interrupts if only generating. Without human origin `"now"` interrupts. Chat and boot prompts use `"now"`; system/boot input keeps nonhuman provenance. During an active operation, inbox input joins its operation ID and returns `delivery: "steer"` without waiting for the reply.
- New input stays in the durable inbox during query initialization, settings changes, manual compaction, Abort/failure and shutdown.
- Steer flag, native input UUID, inbox identities and operation ID persist before SDK submission. Duplicates keep their classification without resubmission. An interrupted old turn's result cannot close the query while accepted steering awaits its own result UUID echo; for echoes capped at 64 UUIDs, retiring omitted inputs also requires the latest accepted UUID, zero queued turns and durable receipts for every pending input. Abort without a durable receipt fails visibly (`claude_delivery_uncertain`) rather than replaying.
- **Input receipts.** Busy steering can persist as `attachment/queued_command` instead of a user row; `submitted:true` and result echoes do not prove consumption. After fsync and immutable-prefix validation, a receipt derives only from a root (non-sidechain) attachment paired with exactly one `remove / absorbed_mid_turn` matching both input UUID and delivery ID, in either append order (native append order need not match creation order). Equivalent queued copies require identical UUID, delivery ID and attachment payload, with one matching removal after every copy; the latest copy is selected. Saved provenance keyed by input UUID supplies inbox/operation identities and input kind. New human receipts are ordinary user messages; peer receipts use the attributed `orb.message` constructor. Their lossless text/image content comes from the already-fsynced accepted delivery body before its existing retirement; unavailable content fails closed. Boot, compaction and other system receipts remain contentless `claude.input_receipt` events. Never infer consumption from timestamps, text, echoes or an attachment alone. Conflicts and duplicate proofs reject with content-free typed errors. Receipts keep `attachmentLine` and `consumptionLine`, append at the journal tail through the atomic index/publication path, and commit before acknowledgement. Boot planning counts human authority at the attachment, never the removal or the appended receipt. Only boot input receipts acknowledge boot operations. A native result is not `claude.operation_finished` (`docs/postmortems/2026-10-15-claude-delivery-uncertain-c9a30a6d.md`, `docs/postmortems/2026-10-25-claude-input-receipt-conflict.md`, question 88).
- Indexed contentless receipts remain immutable and may disappear from display; this limited historical visibility loss is accepted (2026-11-08, PST).
- Control-plane `message-batch-dispatched` edges record turn/steer delivery. Hidden `claude.steering_result` keeps query/operation/result identities, answered and pending input UUIDs and native queued-turn count. Non-steered operations emit nothing.
- Peer input never uses human origin; provenance and attribution: `docs/inbox.md`.

## Boot continuation

The runtime owns restart continuation; native background scheduling is not a restart dispatcher. Normalized root history feeds the shared pure planner `claude/boot-notification.ts`; full journal history keeps identity and budget across compaction.

- Fresh sessions get a silent baseline. Interrupted root work and `sleep_wake` trigger one continuation; otherwise a settled restart supplies passive context; after three claimed attempts since genuine human input, a non-triggering visible decline. Compaction summaries, meta input, boot receipts, system notices, peer messages and receipt-less native deliveries never reset the human budget. Unanswered native deliveries retain interrupted-tail evidence without spending a boot attempt. Boot planning ignores manual-compaction terminals (`work: "compaction"`), native compact echoes/output, summaries and metadata, so a compaction outcome never settles interrupted root work or bypasses an exhausted budget. Durable operation terminals keep Abort/error distinctions.
- A triggering continuation's fsynced platform notice is the claim (a crash after it consumes an attempt), written before ordinary `submit` synchronously owns busy admission. Readiness does not await query initialization or inference. Submission epochs cancel recovery before native admission on Abort. Automatic inputs carry private boot provenance and a receipt-only normalized event; they stay out of the human delivery ledger, so a crash before their receipt spends the claim and permits another bounded notice, never replay. Combined sleep notices carry inbox IDs on the claim for acknowledgement and dedup, including declines.
- Settled restart starts no inference. `HOST_RESTART_CONTEXT` wording is neutral: execution identity proves process loss, not its cause; runtime-only or unknown identity uses conservative wording. Markers and `boot_receipt` provenance deliver all unreceived contexts FIFO as `shouldQuery:false`, `isSynthetic` before the next legitimate input. A volatile set holds context UUIDs enqueued in the current query; a successful zero-turn acknowledgment is skipped only when its IDs are nonempty and all in that set. Settled context forbids repeating completed or aborted work (`docs/postmortems/2026-10-22-claude-timeline-identity-gap.md`).
- Model-facing restart/resume notices (passive context and triggering continuation/sleep-wake) are wrapped in `<system-reminder>` tags, nothing else added, because the SDK merges adjacent user-role inputs.
- Decisions report the `turnResume` health field and persist visible identity/reason/head facts. Claim persistence fails closed; delivery failures persist a sanitized visible notice. Missing human receipts fail closed. Boot policy across harnesses: `docs/lifecycle.md`.

## Manual compaction

Claude uses the shared runtime `compact` command. Admission claims aggregate ownership synchronously before credentials or query initialization; settings, inbox, children, hooks and handoffs stay fenced. `compactionAfterId` freezes the last visible published record. Native input is the string `/compact` with optional instructions, never `client_composed` (which disables slash dispatch); there is no `Query.compact()`. No human message, assistant stream or Luna summary is fabricated.

- The submitted compact UUID survives on the structured native command echo (its `promptId` is not input identity); private provenance hides the echo. Untracked native `isMeta` user entries, including SDK-injected skill bodies (`isMeta`, `turnCompanion`, Skill `sourceToolUseID`), are private metadata. `<local-command-stdout>` envelopes are private only when ancestry reaches registered compaction provenance. Tracked inbox entries and unrelated literal XML stay human messages. No content-pattern filtering; native JSONL is never modified.
- `compact_boundary` is metadata. Only the native `user` entry flagged `isCompactSummary` becomes canonical compaction, keeping its UUID and parent. Automatic compaction uses the same mapping.
- Explicit Abort advances the admission epoch and aborts the operation-owned query controller, never relying on `interrupt()` (the SDK can return `still_queued` and run the command later). Each manual operation owns its query. Ownership releases only after exit, stdout/iterator/hook drain and final history commit.
- Success requires a canonical summary; settled failure or cancellation persists one typed `agent.compaction` outcome before idle, and the generic operation terminal stays hidden so the UI shows one row. Missing summary or uncertain persistence/drain fails readiness, keeps busy and emits one sanitized error frame. Retained manual-compaction journals recover with one typed aborted outcome, never command replay. Typed failure/cancellation events are platform-only, never model context. Display hiding of compaction artifacts: `docs/history.md`.

## History publication

Native records are mapped into normalized history (`docs/history.md`); child transcripts stay local and private.

- Session binding persists before prompts; never restore "most recent" or infer to fetch history. Prompt input UUID → inbox batch IDs persists privately before submission. `inboxMessageIds` publish only after durable native consumption evidence; control-plane replication commit is the sole inbox acknowledgement. Unknown consumption stays visibly blocked; never text-match or resubmit. Required native/journal bytes and directory metadata are fsynced before publishing records or acknowledging alerts.
- **Publication invariant.** A native-only assistant prefix may pass live blocks only when every remaining block has exact UUID ownership in `messageBlocks` and that UUID is an assistant message in the current durable scan. Publish in native order and retire only each matching record's own blocks. Missing or mismatched UUIDs, non-assistant matches and unbound blocks hold publication and fail terminal drain closed; no synthesized identities or retries (`docs/postmortems/2026-10-06-claude-publication-order.md`).
- `claude_stream_identity_gap` fails closed. Its `lastError` includes live/published/native counts, the first unpublished record's ID/type/role, and up to three live block IDs with owner counts and two owner UUID/native-match samples (`missing`, `assistant`, `wrong_role`; zero owners means unbound). IDs outside 1–96 ASCII identifier characters become `null`; matching still uses full IDs.
- **Interrupted thinking.** On a result with `terminal_reason='aborted_streaming'`, capture unowned, nonredacted reasoning block IDs in a volatile set. After `closeExtensions` drains exit, stdout, iteration and hooks, remove only those still unowned before the final flush. Older orphans, text, redacted or owned blocks stay fail closed.

## Diagnostics

- **Initialization failures** show stage, underlying cause and last stderr line in the failure banner. Bounded, credential-redacted stacks/causes, observed exit and stderr go to health `error.diagnostics`, `claude.initialization_failed` history and the control plane's `runtime-failed` lifecycle edge before compute disposal. Limits: 1,024-character summary, 32,768-character stderr buffer, four error-chain entries, 16,384-character diagnostics. Known credentials (including encodings), credential syntax and URL credentials/query/fragments are stripped before truncation (`docs/postmortems/2026-10-12-claude-charts-orb-failure.md`).
- **Stream failures** (`claude_stream_failed`) reuse that capture, adding a 1,024-character context prefix with stage (`sdk_iteration` or `message_processing`), session, query and operation IDs. Stage marks the consumption boundary, not root cause. No wait, retry or replay. Failed health and read-only settings are set before listeners run; listener exceptions cannot replace the original failure (`docs/postmortems/2026-10-15-claude-stream-failed-4647.md`).
- **Assistant and result errors** are recorded at SDK consumption, before shutdown filtering, as `claude.assistant_error` / `claude.result_error`. Visible rows show category and supplied HTTP status (assistant: SDK `error`; result: error subtype, or `api_error` for `success` with `is_error`). Overflow keeps identities, subtype, error flag, error strings, text and nullable `apiErrorStatus` (never inferred), redacted then bounded to 16 strings × 1,024 characters and 8,192 characters of text with `truncated`. Assistant diagnostics include only text blocks. Child errors and healthy results are excluded. Later success clears neither aggregate failure nor diagnostics (`docs/postmortems/2026-10-15-claude-success-failed-operation.md`).
- Initialization failures persist a bounded stage; never SDK text or credentials. Redaction happens at ingestion. Model fallback and quota facts are recorded only from structured evidence.

## MCP

- Queries set `strictMcpConfig: true`: only supplied `mcpServers` and MCP declared by explicitly supplied `agents` are used. Repository `.mcp.json`, user, plugin and on-disk-agent MCP (including subagent frontmatter) are excluded. Settings sources, skills and other settings remain unchanged.
- Static project MCP bindings map to `Options.mcpServers` HTTP entries. OAuth entries use an in-process `McpSdkServerConfigWithInstance` bridge (`@modelcontextprotocol/sdk` raw request handlers) that forwards tools, resources and prompts through a client using the control-plane request-time broker fetch; `tools/list` forwards native JSON Schema unchanged. No guest OAuth login or storage. Project configuration and broker: `docs/mcp.md`.
- Each query owns its bridge. Teardown closes both MCP ends, cancels request transport and awaits admitted operations; the next query creates fresh clients. Upstream list-change notifications, sampling and elicitation are not forwarded.
- **Visibility.** Native MCP failure/recovery edges from per-turn `system/init` go to `claude.mcp` root history: bounded names, closed status/diagnostic categories, allowlisted source (else `unknown`), `observation: native | bridge`. Healthy startup and unchanged levels are silent; pending/unknown never erase failures. Native `failed` is not an auth diagnosis; only `needs-auth` is. Native coalescing lasts for the agent instance across rotations; bridge publishers are query-owned and their visible events say `OAuth bridge:`. Bridge success cannot clear native failure, and native `connected` does not prove upstream authorization. Rejected: `mcpServerStatus()` control requests (latency, lifecycle, extra config/error fields) (`docs/postmortems/2026-11-06-claude-mcp-authorization-report.md`).

Model and effort settings: `docs/agent-context.md`. Per-call model usage: `docs/model-usage.md`.
