## Selected implementation contract (2026-09-15)

Extend the existing personal-instructions pattern, not the repository filesystem or a new prompt-management framework:

- Store one readable Markdown document and monotonic revision per project in PostgreSQL. Migration `020_project_instructions.sql` adds `instructions_content` (empty by default) and `instructions_revision` (initially 0) to `projects`. Do not include document bodies in fleet/list responses. A separate table is unnecessary for a one-to-one document with the project's lifetime.
- `GET /api/v1/projects/:projectId/instructions` returns `{content, revision}`. `PUT` accepts `{content}` and returns the atomically saved snapshot. Reuse personal text validation: 64 KiB UTF-8, preserve whitespace, reject NUL/unpaired surrogates. Explicit last-applied-wins assignment, no autosave, stale-tab CAS, blind replay or version-history UI. Save conflicts once project deletion begins; missing project is a typed 404. Reads are non-cacheable. A lost save acknowledgement retains the draft without claiming the assignment failed to commit.
- `GET /runtime/v1/project-instructions` uses the current active-incarnation bearer and derives the project from that orb, never a caller-supplied project ID. Read once after bootstrap authentication and before session/resource initialization. Failed reads visibly block readiness rather than silently substituting empty/stale content. Use the existing bounded boot-fetch and typed error pattern, not a new retry/reconciliation service.
- Add a virtual `pi-orb:project/AGENTS.md` source using `agentsFilesOverride` in `apps/orb-runtime/src/pi/resource-loader.ts`. The repository already uses this public SDK boundary for personal instructions; the SDK context-file example explicitly supports additional virtual sources. No SDK fork, boot hook, `AGENTS.md` append/overwrite, checkout commit, or managed guest file is needed.
- Composition is personal source → unchanged native context-file list → additional project source. The distinct virtual source path identifies the supplemental project document; the editor is explicitly named “Additional project instructions” for accessibility. Source order is not a new enforcement/priority mechanism, and does not claim to unconditionally override narrower repository instructions. Content conflicts remain normal instruction interpretation, not a merge engine. Real-SDK contracts pin exact additive context and immutable reloads; runtime E2E inspects actual model requests.
- Capture the project snapshot by value for that runtime's lifetime, just like personal instructions. Saving does not send a message, wake or restart compute, interrupt inference, or fetch a new value on resource reload. Fresh and resumed coding sessions adopt at the next runtime start. Empty content removes only this managed source at that boundary. Existing conversational memory is not erased by clearing future instructions.
- All independent same-project orbs, including CLI-spawned orbs, use the same saved project document at boot. The installed subagent fork's normal full-prompt inheritance already carries the parent's captured instructions to default general-purpose children, even when the project is edited before the child starts; the real subagent E2E pins that property. No new child-resource hook or fork change is needed. Deliberately customized replacement/portable child prompts retain the extension's normal semantics rather than introducing an instruction bypass-prevention system. Separate Luna naming/summary prompts remain unchanged.
- Before readiness, append an edge-only non-model-context `pi-orb:project-instructions` history entry with applied revision and SHA-256. The enclosing orb already owns immutable project identity, so duplicating a project ID in every entry was rejected as unnecessary. Flush through existing native session durability and replicate normally. Initial empty revision 0 and unchanged restarts stay silent; changed/cleared snapshots record an adoption edge. Never log instruction bodies. Adoption failures use the existing durable startup-failure path and visible orb errors. Configuration persistence and actual runtime adoption remain distinguishable without a healthy-state transcript row or new reconciler.

### Selected Config tab behavior

Raw Markdown, explicit Save, an unsaved indication only while dirty, empty content allowed. Project identity appears once in the enclosing header. Do not label the editor as the repository's actual `AGENTS.md`, or use the personal editor's `~/AGENTS.md` label: neither is the file being edited. No Markdown toolbar, templates, explanatory cards, new composer commands, or combined personal/project scope selector.

Reuse the personal editor's production safety model: initial fetch failure gives Retry, not an editable fake empty file; save failure retains the draft; disable mutation/dismissal during a pending save; only acknowledged persistence produces `Saved · next orb start`. A clean retained editor is non-mutable from its activation render until its refresh owns the state; gating only in the later effect permits that refresh to clobber an edit. An effect-free server-render regression pins this boundary. Dirty retained drafts reopen without refresh. Closing retains unsaved content in page memory, scoped by project; navigation/reload discards unsaved drafts. Do not put readable instruction authority in localStorage. Config tab switches must preserve independently owned drafts. The selected tab adds no document route. API reads/writes return a project-specific “Project doesn't exist” error instead of silently creating a document or redirecting; the existing project/orb missing-resource routes are unchanged. Evidence: `docs/postmortems/2026-09-16-release-validation-blockers.md`.

## Five UI proposals (selection and rejected alternatives)

1. **Config tab — selected and implemented.** Existing project gear → `Instructions`, alongside General / MCPs / Secrets, opens the same 560px Config geometry with a dedicated Markdown body. Works from existing dashboard/index project configuration entry points. No new permanent icon, distinct from the personal Home gear, and no metadata mixed into the editor. Tradeoff: a fourth tab and moderate room for long documents.
2. **General fold.** Existing project gear → General → `Additional instructions`, a disclosure below name and repository. The instructions section has its own Save, independent of metadata changes. Smallest navigation change. Tradeoff: general settings become taller and two separately owned saves share a surface. The study keeps metadata read-only so it cannot imply a combined persistence contract.
3. **Column notebook.** An `Instructions` disclosure below each dashboard project header expands an editor within that column. Project ownership is spatial, and the rest of the fleet remains visible. One project is open at a time in the study; drafts remain independent when switching. Tradeoff: narrow 316px desktop writing width, permanent dashboard row, and displaced orb rows while open.
4. **Project folio.** An `Instructions` link below the project header navigates to a full-page `project / Instructions` document with dashboard return, a stable Save footer and up to 960px writing width. Strongest long-document editor. Tradeoff: leaves the fleet and adds navigation. A production version should use an addressable project route; the study only simulates navigation and does not implement missing-resource handling.
5. **Conversation sheet.** The existing project gear in the orb index opens a 480px right-hand Config sheet with Instructions selected. It overlays history but ends above the independent composer. On phones, reach the same project configuration through the orb's overflow menu; no desktop index on phones. Good when a conversation reveals a recurring project preference. Tradeoff: conversation occlusion, a changed Config presentation in the orb view, and less height with a phone keyboard. The project named by the gear remains the sheet's scope even when it differs from the currently open orb's project.

Config tab minimizes additional UI and is the sole selected surface. General fold, Column notebook, Project folio and Conversation sheet are rejected alternatives for this slice, retained above with their tradeoffs. No second entry point, scope switch, new route, autosave, live-update machinery, revision-history UI or settings framework is introduced.

## Implementation and test-first qualification

Snapshot validation, bounded boot-fetch logic and edge-only revision/hash adoption are shared with personal instructions rather than copied into parallel mechanisms. The project gear retains the draft in a ref across dialog mounts; the panel owns load/save UI state and guards late reads on unmount. Panels remain mounted across tab switches. The MCP OAuth return path now selects tab index 2; keyboard traversal is General → Instructions → MCPs → Secrets.
