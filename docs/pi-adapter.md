# Pi integration

## Pi 1.4 task recovery (decision 2026-10-22; local, undeployed)

Sleeping tasks preserve checkpoint and wake time in PostgreSQL and remain unfinished work through recovery demand, busy and drain checks. Host timers use Harness time; custom documents explicitly retain their delta policy. Chord default contexts carry no-op telemetry, not persisted propagation carriers.

Five interrupted starts without progress park a task. Safe report categories/task identities/counts enter existing lifecycle edges, never private exception contents. Parking keeps the browser attachable: a derived snapshot notice becomes the existing `server.error` after synchronization, including late stable-handle attachment. Abort abandons the interrupted root turn; fresh input can then proceed. Stop/Start, automatic reopen and queued input do not retry it or reset its count. Independent parked children leave root health available; `cancel_subagent` commits cancellation control, calls the bound public Harness abort, then waits. The `central_agent_paused` error clears when the operation settles; unrelated errors remain. No new retry control or persisted setting. State scope: `docs/pi-durable-evaluation.md`; qualification: `docs/testing.md`.


Pi runs centrally in the control plane using Durable and PostgreSQL. Execution hosts provide workspace operations, hooks and guest services. Claude runs natively on its host (`docs/claude-agent-sdk.md`).

**Central code-mode contract (Pi 1.3 native adoption decided 2026-10-16; qualification in `docs/testing.md`):** root and generic children expose only `codemode`; internal authorized callables remain available. QuickJS has a 256 MiB limit; emitted output is capped at 1 MiB text, 32 MiB aggregate encoded images plus text, and 4,096 items. Each script shares fixed tool/global callback caps: 8 outstanding, 256 cumulative calls, 8 MiB cumulative UTF-8 arguments and 64 MiB cumulative UTF-8 replies. Worker consumption releases outstanding admission; overflow aborts callbacks, returns `resource_limit` and commits no sandbox store changes. Earlier external effects are not rolled back. Namespace discovery includes unchanged `orb` names and MCP resources/server instructions; the retained client is not the full SDK/TUI/model-helper surface. Nested output/failures materialize into script results, not unconditional parent stdout; bounded progress retains execution-wait status. Private PostgreSQL spills (16 MiB/artifact) remain readable off-host; the historical process gate proved creation/control-plane restart/off-host read (`docs/testing.md`), not 1.3 qualification. Archived public excerpts do not depend on private references. Future native `store`/`load` state is rewindable and forks as of history; legacy saved values do not carry over into a new native store (user-approved 2026-10-16, PDT; `docs/open-questions.md`, question 81); existing legacy records and native stores remain untouched; failed/overflowed scripts do not commit sandbox state. Required Git/context acquisition precedes the first model turn; only VM-backed calls await execution readiness. Boot hook reports remain visible through compute health. Contract: `docs/pi-durable-evaluation.md`.

Tool-only registrations retain preparation, authorization and cancellation; children persist an explicit callable whitelist excluding spawning/subagent/ambient capabilities. Root and child native `AgentDoc.modelTools` expose only code-mode; `tools` controls internal callability. Replay refusal prevents new nested admissions, not independent retries of already-admitted replay-safe pending children. Completed callback receipts are reused; external effects are not physically exactly once. Retried children recheck current authorization/environment without repeating admission-time preparation/hooks; parent cleanup aborts them. Private text spills, inline images, replay-aware charts, argument-key-only presentation and the resource controls below remain pi-orb policy. Sandbox accounting drains through actual worker exit, not merely a returned result or `close()`. Design and persisted-state scope: `docs/pi-durable-evaluation.md`. Earlier measurements and 1.1 receipts below are historical, not 1.3 qualification.

Deferred MCP tools retain discoverable full raw JSON schemas/results, including arrays/null in `structuredContent`. **Retained read-image policy (2026-10-16).** Native `createReadTool({ images })` uses the public `ImageProcessor` hook to return original PNG/JPEG/GIF/WebP bytes up to exactly 20 MiB raw, independent of dimensions. Native provider resize defaults would narrow the existing application read contract, so this hook deliberately ignores model resize limits without changing model configuration. It does not decode, resize or transcode. Unsupported formats and raw sizes above the cap return `undefined` for native `unsupported_image` diagnostics. Native read retains file/path resolution, sniffing, text handling and diagnostics; scoped immutable resources and private artifacts remain checked before delegation. Remote whole-file reads retain their stronger 16 MiB cap; callback, output and VM limits above remain unchanged. No persisted state changes.

**Orb result contract (decided 2026-10-22).** All `orb_*` tools and `notify_parent` return native structured objects, with per-tool success schemas and `{error: {code, message}}` failures. Alert successes include `recordId` and the native `duplicate` receipt. Failures retain `isError` and error diagnostics; JSON text remains readable in direct calls and history. This POC output contract changes directly, without dual support. Tool descriptions and prompt prose are unchanged.

**Raw MCP validation (2026-10-16).** Check original arguments against the server's original JSON Schema before native coercion, preparation hooks, authorization, per-call credentials or effects. Discovery credentials are separate. Preserve explicit JSON null; only omitted/undefined arguments default to `{}`. Compose native preparation only after strict acceptance. Invalid input receives a fixed sanitized rejection through the Harness-required throw; private input/error values must not reach model output or public details. Full raw schemas, deferred discovery metadata and complete structured MCP results remain intact.

**Runtime MCP resource discovery (2026-10-16).** Upstream Pi 1.2 [#10526](https://github.com/earendil-works/pi/issues/10526) makes resource/template discovery lazy; tool discovery does not eagerly query optional resource lists. With an established session, HTTP 404 means session expiry: the native client reconnects/retries once, and non-success bodies remain sanitized. HTTP 200 carrying JSON-RPC `-32601` instead means an unsupported optional template method and permits an empty-template fallback. Do not reinterpret an HTTP 404 body as that fallback. This uses native transport behavior, not a first-party transport rewrite; fixture qualification is separate (`docs/testing.md`).

**Existing-orb skill-bundle waiver (user-approved 2026-10-19, PDT; [PR 149](https://github.com/schani/pi-orb/pull/149)).** Existing orbs whose `pi-orb-platform-1` snapshots lack the new codemode skill are accepted as incompatible; existing-orb readiness is not claimed. No marker bump, persisted-state change, fallback, SQL migration or runtime fix is authorized for this incompatibility. This waiver excludes unresolved non-UI image-test timeouts, new failures and ordinary exact-head qualification. It authorizes neither merge nor deployment.

## Code-mode CPU budget (2026-10-09; implemented locally, not deployed)

Every central code-mode execution, across root/child agents and orbs, receives the same process-wide atomic CPU credit pool. Credit replenishes at one CPU microsecond per elapsed wall microsecond, with at most 20 ms of unused credit. Checkpoint overshoot remains debt, including across execution cancellation and idle/reentry; starting another worker never grants another budget. A 20 ms main-thread timer exists only while executions are active and wakes parked workers. It uses actual monotonic elapsed time, not timer tick count.

The bounded worker charges its cumulative thread CPU from startup, then charges deltas at QuickJS interrupts, callback replies and outgoing messages. Exhaustion parks only that worker with `Atomics.wait`; returning normally from the interrupt preserves the VM stack, promises and store. Cancellation is checked between waits, which have a 20 ms ceiling; the sandbox's original host deadline/abort/close terminates workers, including parked ones. The existing wall deadline includes CPU-budget waiting. Host callbacks keep their existing independent bounds.

This is cooperative accounting, not a kernel CPU quota: native operations between checkpoints can burst, abrupt termination before a checkpoint can leave an uncharged tail, and main-thread callbacks/serialization, shared WASM compilation and runtime background threads are outside worker credit. The independently managed two-vCPU Cloud Run allocation supplies serving headroom; no application limiter guarantees that ingress never returns 429.

Each terminal tool result durably retains `details.cpu`: `budgetCores`, `cpuMs`, `throttledMs` and `checkpoints`, without script contents. Counters describe observed checkpoints; forced termination can omit the final interval. The result text reports budget waiting of at least 100 ms. The rollout monitor requires revision-scoped Run CPU metrics and treats ingress 429s as a regression even when application probes succeed. The dependency checkpoint/custom-worker-data hooks are sealed in `patches/pi-codemode.PROVENANCE.md`.

**Charts (implemented locally 2026-10-13; native integration 2026-10-16; not deployed).** Code-mode scripts call `await chart(spec)` to show the user a chart (`docs/web-ui.md`, transcript charts). The host global validates and normalizes the spec (`parseChartSpec`: ISO or epoch-ms times to epoch ms, null points dropped, ≤6 series, ≤5,000 points, ≤40 bars, unique series names, http(s) `source`) and rejects into the script with the validation message; at most 8 charts per script. Successful native chart journal entries derive `LiveDoc` charts atomically; `details.charts` commits with native completion, so data never reaches the model; accepted charts survive reopen, error and cancellation. The callback counts against the shared callback caps. The bundled `charts` skill (`apps/orb-runtime/skills/charts/SKILL.md`) documents the spec, automatic styling, limits and unsupported forms; a test keeps its limits equal to the protocol constants.

Local production-worker Linux/two-CPU load with 1/2/4 busy workers measured 1.00/0.99/1.01 process cores and HTTP p99 of 6.2/3.4/3.9 ms over eight-second windows after warmup. This emulated Docker test establishes aggregate throttling and main-thread responsiveness, not Cloud Run admission or a historical hotspot. Deterministic schedules cover shared credit, overshoot, delayed refill, cancellation/reentry and cleanup; real workers cover callback/job/store preservation and parked abort/timeout/close. Evidence and release qualification: `docs/postmortems/2026-10-09-control-plane-cpu-429.md`, `TODO.md`.

## Code-mode memory observability (2026-10-11; implemented locally, not deployed)

Purpose: attribute the shared control-plane OOMs (`docs/postmortems/2026-10-09-central-durable-oom-recovery.md`). Cloud Profiler cannot see worker threads (evaluation in `docs/deployment.md`), so code-mode workers report their own memory. Profiling the main isolate with it is deferred (2026-10-11): `@google-cloud/profiler` 8.1.0 adds two high and eight moderate audit advisories, and forcing fixed `protobufjs`/`uuid` versions breaks its install.

**Per worker (decision 2026-10-29).** At every CPU checkpoint (startup, QuickJS interrupts, messages) the bounded worker writes `used_heap_size + external_memory + owned QuickJS wasm capacity` and the running peak into a shared buffer. Node 26.13.0 omits both initial and grown exported wasm capacity from its host counters, including the actual QuickJS module. The sealed SDK publishes a per-VM getter before prelude/guest execution; each read uses the current memory buffer and returns zero after disposal. Completion messages sample even quiet scripts before disposal; peak bytes remain retained. No initial capacity is subtracted. Native module/QuickJS contract tests reject engines that start counting these bytes, preventing double-counting. QuickJS's independent allocation cap is unchanged and does not bound aggregate worker RAM.

Earlier Node 24 measurements counted wasm in `external_memory` (external = wasm + 4–5 MiB), so direct wasm accounting was rejected as redundant and insufficient for callback replies held in the worker heap. Node 26's omission requires owned-capacity accounting alongside, not instead of, host counters. The SDK owns the getter; first-party code does not reach into QuickJS. Host-side `worker.getHeapStatistics()` remains rejected because the sandbox does not expose its `Worker`. Regression: `apps/control-plane/src/adapters/durable/tools/wasm-memory.test.ts`.

**Per invocation.** Each terminal tool result retains `details.memory.peakBytes` next to `details.cpu`. An invocation that fails for resources emits one `lifecycle: orb=<id> codemode.resource_failed kind=<out_of_memory|output_limit|callback_limit|sandbox_exit> peak_mib=<n> conversation=<id> call=<id>`. Timeouts and aborts are not resource failures.

**Per process.** `tools/codemode-memory.ts` tracks live workers. While at least one is live, every 10 s it writes one stdout JSON line:

```json
{"message":"codemode.memory","workers":4,"worker_sum_mib":377.7,"worker_max_mib":210.9,"worker_max_orb":"<orb id>","rss_mib":511.7,"heap_used_mib":17,"heap_total_mib":34.2,"external_mib":8.5,"array_buffers_mib":0.1}
```

The timer starts with the first worker and stops at the first tick without one, so an idle process logs nothing and short scripts keep the cadence. Node writes stdout pipes and files synchronously on Linux, so the last sample before an OOM kill (at most 10 s old) is not lost in a buffer. Sampling is a deliberate level, not an edge: the kill is a SIGKILL without warning, and threshold edges would miss growth between crossings (`docs/lifecycle.md`).

**Local measurement (2026-10-11).** Four concurrent workers held at a callback through the real `codemodeTool` (`.context/memprobe.ts`). Linux Node 24.21.0 (2 CPU / 4 GiB container): worker sum 377.7 MiB against a process RSS increase of 376.1 MiB; per worker idle 11.8, 400k objects 93.1, 50 MiB buffer 61.9, 200 MiB allocated then freed 210.9 (wasm memory never shrinks during a run), QuickJS out of memory 250.9 MiB. macOS Node 24.6.0: 375.3 against 372.5 MiB.

**Usage.** Samples:

```
resource.type="cloud_run_revision"
resource.labels.service_name="pi-orb-issuer"
jsonPayload.message="codemode.memory"
```

The sample before a kill: add `timestamp<="<kill time>"` and take the newest entry; kills appear as `"Memory limit"` platform entries. Resource failures: `textPayload:"codemode.resource_failed"`. Suggested log-based metric for live workers, charted against `run.googleapis.com/container/memory/utilizations` (`gcloud logging metrics create codemode_live_workers --config-from-file=metric.yaml`):

```yaml
filter: resource.type="cloud_run_revision" AND resource.labels.service_name="pi-orb-issuer" AND jsonPayload.message="codemode.memory"
valueExtractor: EXTRACT(jsonPayload.workers)
metricDescriptor: {metricKind: DELTA, valueType: DISTRIBUTION, unit: "1"}
bucketOptions: {linearBuckets: {numFiniteBuckets: 32, width: 1, offset: 0}}
```

The same shape with `EXTRACT(jsonPayload.worker_sum_mib)` charts code-mode memory.

## Placement and admission

Pi harnesses run in the control plane with PostgreSQL authority across process, Docker and GCP hosts. Central model/auth/skill helpers still use Pi coding-agent and inference uses Pi AI. Fresh conversations default to Astra/high; resumed settings remain per orb. Manual Pi compaction returns typed `unsupported` without allocating an operation, changing history or invoking a model.

MCP and QuickJS codemode run centrally with scoped callbacks. Canonical MCP names are `mcp__server__tool`, without aliases. Owned background MCP discovery never gates startup/local tools. Pending search, automatic native alerts/model context and optional status retry: `docs/mcp.md`. Local preflight refreshes root/existing-child catalogs through native registry/Conversation APIs (`docs/pi-durable-evaluation.md`). Generic child tools provide start, steer, observe/wait, list and cancel without profiles. Agent-facing `orb_*` tools call application services; the CLI remains available for shell scripts and boot hooks, including authenticated local alert forwarding into central native history without model input. Terminal guest initialization failures surface in health. Owner-scoped Luna summaries are bounded/private and best effort: VM idle-stop leaves central summaries running without closing the Harness; graceful sleep/archive wait for pending summaries and outcome telemetry before closing owner resources; explicit Stop aborts/drains them. A control-plane crash may lose notifications without affecting completed root history. Detailed policy and qualification: `docs/pi-durable-evaluation.md`, `docs/testing.md`.

**Independent central execution:** model/authority ownership follows durable agent-admission authority independently of VM incarnation, readiness and failure. Authenticated central inference, MCP, coordination, inbox and browser attachment remain available off-VM; each host-backed tool gets an immediate lazy facade and pins one guest binding for its entire invocation. Cancellation/admission are checked after readiness and before effects; invocation cleanup releases execution leases. Root/child/submission work warms eligible execution in parallel; visible presence keeps running compute warm. Explicit Stop/sleep/admin authority overrides demand; read-only reopen preserves unfinished work without scheduling or reporting it active. Central repository instructions and skill metadata load from the pinned Git snapshot before the first model request and remain stable for the context. Execution readiness carries only execution metadata; explicit filesystem reads use the live workspace once ready. Policy: `docs/lifecycle.md`, `docs/open-questions.md` question 73 (Pi Durable). Qualification: `docs/pi-durable-evaluation.md`, `docs/testing.md`.

**Peer source preservation (2026-10-14; local, undeployed).** Central Durable retains complete existing receipt `system` metadata through atomic/public projection. Native input adds a generated stable-ID label: peer agent input, not a human request or explicit consent. Public peer content removes only that generated label after validating receipt provenance. Native receipt content and metadata remain available after reopen; no sender-name snapshot or new receipt identity. Central Native recovery keeps its existing task/submission authority, without introducing human budget resets.

**Native input admission (decision 2026-10-16):** new central inputs check Sleep and browser-behind-inbox policy through the read-only lease boundary before native submission. Public native request-identity lookup precedes that check, including admitted-before-receipt-finalization inputs; only known Sleep/held-inbox policy refusals recheck identity to preserve concurrent admission and return typed caller-visible errors without failing the harness. Preflight database/ownership faults and fatal identity-read failures seal admission, fail health, publish the existing storage-failure edge/error once, and join native Storage and owner-resource cleanup. Native invalid, effect-free read requests remain nonfatal. The atomic commit guard remains authoritative: a race after a successful preflight still fails the Session and requires real close/reopen. Native commit failures remain fatal; only callback refusals before storage writes are recoverable. Existing fatal storage events and public errors retain failure visibility.

**Central input identity (2026-10-03):** browser request IDs deduplicate native submissions; only durable control-plane inbox UUIDs enter `inboxMessageIds` for SQL acknowledgement. POC history projection failures emit durable `history.projection_failed` edges and public `history_unavailable` frames. The integrated PostgreSQL candidate requires native mutation and required public projection/enrichment/cursor/dedup updates in one transaction, with applicable receipts/admission/owner fencing; notifications follow commit and lost notifications use cursor catch-up/replay. A domain-owned unit of work goes through the immediate adapter neighbor; asynchronous projection repair is not an atomicity substitute (`docs/history-replication.md`). Evidence: `docs/postmortems/2026-10-03-durable-process-qualification.md`.

## Product history

Committed root entries project into normalized product history in the same PostgreSQL transaction as native state and receipt updates. Private prompts, tool configuration and child transcripts remain outside public projection. Preserve source identity, ancestry, timestamps, compaction boundaries, inbox provenance and typed failures. A projection failure cannot acknowledge delivery or retire live output. Passive transcript/detail reads never load a Harness or wake compute (`docs/history-replication.md`).

Code-mode chart specs commit with terminal results; only validated chart leaves reach browser detail projection. Native nested-call summaries belong to their parent result, not invented standalone tool rows (`docs/runtime-protocol.md`).
