# Pi harness

Pi runs centrally in the control plane on Pi Durable with PostgreSQL authority. Execution hosts (process, Docker, GCP) provide only workspace operations, boot hooks and guest services. Claude runs natively on its host (`docs/claude.md`). The Pi family (`@earendil-works/{chord,pi-ai,pi-codemode,pi-coding-agent,pi-durable}`) is pinned at one version; upgrades are routine.

**Why Durable, centrally.** Durable supplies committed task progress, ownership, recovery and replayable code-mode that pi-orb otherwise built around the coding-agent SDK, and central placement removes the guest-history → replica split. Upstream owns orchestration; pi-orb adds policy and presentation. Rejected: one local Harness per orb (keeps the replica machinery) and a first-party code-mode wrapper (maintenance burden).

Pi-ai supplies inference through native `Models`; pi-coding-agent remains only for OAuth login, skill helpers (`formatSkillsForPrompt`, strict YAML `parseFrontmatter`) and model metadata.

## Placement and ownership

- One metadata-only stable agent handle per orb lives for the life of the control-plane Node process; the Harness and its resources load and unload separately. Browser subscriptions bind to the handle and survive unload/reopen; generation checks discard stale owner publications. Passive hello reads PostgreSQL without opening the Harness; before the first public header it returns empty `conversation:<orbId>` history (the eventual native identity), so attachment and pending Abort work before Git acquisition completes. Agents are JavaScript objects in the shared process: no per-orb OS process or WorkerThread. Stop/Sleep close only that orb's Harness.
- The browser's live route attaches directly to the central agent plane; history and commands never proxy through the guest. Explicitly stopped or sleeping views attach read-only without resuming retained work; fresh authorized inbox input can supersede that inhibition. Execution HTTP (workspace tools, guest services, `/execution/ready`) is a separate authenticated, incarnation-fenced boundary (`docs/runtime-protocol.md`). A tool waiting for execution shows a bounded execution-wait reason, cleared on readiness or terminal outcome.
- Model and authority ownership follow the durable agent-admission generation, not the VM incarnation. Inference, MCP, native control-plane tools, inbox delivery and browser attachment work before execution readiness and survive VM failure or idle-stop. Host boot failure does not end the conversation.
- Execution factories return immediately. Each host-backed tool invocation lazily acquires one immutable guest binding and holds its lease for all filesystem/shell calls of that invocation. Cancellation and admission are checked after readiness and before effects; the lease releases at invocation completion. Unsafe effects never retarget or replay. Execution demand and warm-keeping: `docs/lifecycle.md`.
- Unloading (conditions: `docs/lifecycle.md`) defers while work, children, waits, leases, pending persistence/publication or summaries remain, then recheck that the host is still stopped. Never abort work, reopen resources or boot compute merely to unload. Rejected: LRU/resource-pressure eviction.
- Owner leases use the database clock. An instance-bound drain capability lets already-admitted cleanup finish after admission revocation; it never permits new submission, model or effect dispatch.
- Native failure can close storage before owner-fenced drain starts. A matching database-validated owner may finish draining already-closed storage without new writes. Join Harness/resource teardown before compute destruction; genuine cleanup/fence failures stay errors (`docs/postmortems/2026-10-18-central-drain-close-race.md`).
- After storage-capability verification, a database owner-guard rejection returns typed `owner_lost`, not a cleanup error or drain-write permission. Native Harness/storage, publication, summaries and resources still finish before manager replacement. Foreign storage, unavailable SQL and cleanup failures stay errors; an aborted ownership signal alone proves nothing. Failed authority releases retry only the idempotent database release, never teardown. Renewal/drain cause codes and the final close outcome/stage use existing lifecycle edges (`docs/postmortems/2026-10-23-agent-lease-loss-drain.md`).
- The manager owns every successful open before admission revalidation, including superseded ones. Ownership is `owned | retiring` with one joined retirement result; only success removes it. Retiring owners are not reused; cleanup failure stays visible to shutdown/unload callers and blocks replacement without repeating teardown. Admitted openings stay serialized by the existing queue.
- **Startup compatibility.** A locked ownership-acquisition check precedes owner/metadata writes and refuses archived, archiving and deleting orbs; native transactions and ID allocation recheck it under the orb/owner fence. Startup compares the published session header with the native root `orb.identity`; without one, only the exact prospective initial session ID is compatible. Conversations from the removed host-Pi backend reject initialization and new messages with terminal `legacy_backend` (disposition `create_new_orb`, "This orb uses the old Pi backend. Create a new orb to continue.") before ownership or private initialization; malformed identity or missing cursor/head coverage is terminal `history_integrity`. Public history, archives and workspace stay intact. Startup progress checks read bounded identity metadata only, never transcript scans.
- **Retirement fences.** Suspension carries the observed admission generation and advances the manager's authority floor, so an old Stop cannot close newer input and an old sampled open cannot undo revocation. Queued mutations recheck closing and durable admission when their serialized effect begins; native alerts revalidate the expected generation inside the PostgreSQL receipt/effect transaction. Retirement derives accepted cancellation from the current run task's committed `abortRequested`, even without a terminal assistant; historical receipts and reused operation tokens cannot select it, and only completed operations enqueue Luna summaries. Pending sleep/archival does not revoke admitted continuations, but rejects new spawn/sleep/archive/delete admission. Drain preparation is a serialized read-only inspection, not admission.
- A shared control-plane OOM interrupts every central agent; it is not evidence of guest failure. Recovery-task counts and instruction-adoption logs do not establish subagent counts or memory attribution. User-visible diagnosis distinguishes confirmed OOM from an unknown memory driver (`docs/postmortems/2026-10-09-central-durable-oom-recovery.md`).

## Persistence

- Durable's `Storage` contract is implemented in first-party PostgreSQL queries with explicit orb-namespace predicates, table names and bound positional parameters; the same adapter runs on PGlite. Explicit SQL is preferred over dialect translation so scoping and binding stay reviewable. The upstream storage conformance suite runs on both. Conversation, task and submission scans default ascending, entries descending; a cursor carries and enforces its order.
- Private native state (agent history, execution state) and the public transcript are stored separately on purpose: independent privacy and lifetimes. Archive and delete sequencing: `docs/teardown.md`. Rejected: canonical native entries with thin public references (retention coupling) and a separate SQLite authority (second persistence system).
- **Atomic commit.** Each causal mutation commits native state plus all required public projection, enrichment, cursor and dedup updates, with applicable receipts, admission and owner fences, in one PostgreSQL transaction. Readers never see half-state; notifications follow commit and lost notifications recover through cursor catch-up. Asynchronous projection repair is not a substitute. The domain unit of work goes through the immediate adapter. Record model, projection rules and storage schema: `docs/history.md`.
- Grouped `Storage.commit(batches, receive, context)` runs all accepted batches in one SQL transaction with per-batch sequences and lease/owner fencing. A native-check refusal commits only the valid prefix; SQL, owner, projection failures and ambiguous COMMIT are not check refusals. After all accepted batches are durable, `receive(index, seq)` runs once per accepted batch, synchronously and in order. Observer errors cannot undo a committed transaction. Repeating native `submit(tx, draft)` in one transaction is not an atomic batch (the second write hits `ReadAfterWrite`), so first-party `submitMany` stays.
- Effect-free invalid requests are recoverable `StorageRequestError`s. I/O, corruption and authority loss are fatal Session failures; `SessionFailed` retains typed owner-fence causes. Native commit failures are fatal; only callback refusals before storage writes are recoverable.
- Native records upgrade lazily: typed reads materialize old versions in memory and the next mutation persists the current version; the scheduler upgrades live task checkpoints on advance. `durable_pg_tasks.status` admits `sleeping`; sleeping tasks keep their checkpoint and wake time and count as unfinished work for recovery demand, busy and drain. `CodemodeStoreDoc` writes a base after 64 deltas; first-party custom documents set `checkpointWhen: () => false`. Host timers use Harness time. Chord telemetry contexts are no-ops; no trace carriers are persisted.
- **Progress is memory-first.** Native progress is deferred about one second (not a hard bound) and watchers see it before storage. A crash can therefore shorten recovered assistant entries, interrupt tool output, and omit an unstored attempt or its usage, changing recovered history and later model context. Intents, checkpoints, terminal receipts, journals, store values and the final flush stay durable. Accepted for simplicity. Rejected: an immediate-progress patch and stored-only watcher reconstruction.
- The `pi.provider` conversation document carries the Codex prompt-cache session (`docs/postmortems/2026-10-12-durable-codex-prompt-cache.md`).
- Passive transcript and detail reads query PostgreSQL; they never load a Harness or wake compute.

## Context

What enters the model context, in what order, and when it is adopted: `docs/agent-context.md`. Pi-specific acquisition:

- **Repository pin.** Before the first model turn, a selective shallow, blob-filtered control-plane Git fetch persists the instruction file, complete repository skill files, manifest and exact SHA in PostgreSQL. Eager host allocation runs concurrently. Fresh initialization waits for that SHA, checks out `main` at it, then runs hooks; resuming a retained workspace never resets dirty files. Owner-scoped GitHub grants authenticate when present; without a grant, public access is noninteractive with redirects and credential helpers disabled. Broker failures stay failures; inaccessible private repositories fail acquisition. Checkout semantics: `docs/host-provider.md`.
- **Selection.** Instructions: first present of `.pi/AGENTS.md` → `AGENTS.md` → `.agents/AGENTS.md`, never merged. Skills: `.pi/skills` if it exists (even empty or invalid), otherwise `.agents/skills`. Tracked repository-local symlinks resolve at the pinned commit within the repository, cycle-safely; absolute/escaping targets are rejected. No ambient home, Claude or extension discovery; executable repository Pi extensions are never loaded centrally. Bundled `/opt/pi-orb/skills` is separate and canonical.
- **Failure policy.** Confirmed absence is valid. Unreadable resources, unsafe paths/links, integrity failures and required instruction failures block visibly; they never become empty context. Invalid repository skill YAML, UTF-8, metadata or duplicate names inside the repository warn and skip that skill; content-free `{path, code: "invalid_yaml" | "invalid_utf8" | "invalid_metadata" | "duplicate_name"}` diagnostics persist with the snapshot and return as `OrbView.resourceWarnings` after reload. Repository/platform name collisions and bundled-skill failures are fatal (`docs/postmortems/2026-10-09-glideos-delivery-blocked.md`). Content-free acquiring/ready/failed edges persist; `resources.ready` records the commit and repository file/byte counts.
- **Name-only projects.** A null repository URL skips Git acquisition only; managed instructions and platform skills still load, and the first context needs no checkout, credentials or execution readiness. `resources.ready` records a null commit and zero files. A URL added before any snapshot exists is acquired at the next context open (Stop/Start); the first successful pin stays authoritative after later URL edits or removal. Acquisition never clones into or rewrites the retained workspace.
- **Reads.** `SnapshotResourceReader` resolves POSIX-normalized paths only against adopted keys: relative repository paths and canonical `/opt/pi-orb/skills/...`. It never reads the control-plane filesystem or translates absolute workspace paths. Bundled reads stay private and offline even when execution is ready; a path that starts with the bundled prefix but escapes it fails. Repository reads use the pinned files off-host and the live workspace once execution is ready. Private artifact paths keep their ownership fences. Execution readiness carries only cwd, incarnation, PID, checkout commit and hook reports.
- Skills appear as metadata (`formatSkillsForPrompt`, indirect); bodies are read on demand. Not exposed: `/skill:name` and prompt templates, `SYSTEM.md`/`APPEND_SYSTEM.md`, session-tree/branch controls, the follow-up queue. Inbox delivery submits content directly.

## Tools and code-mode

- The model sees only `codemode`. Every other tool registers with `callers:["tools"]` and is callable only from scripts. Each root open configures `tools:null`, `modelTools:[codemode]`; public `Conversation.configure` stores names in native `AgentDoc.tools`/`modelTools`. Native validation/preparation runs once, then catalog authorization/admission precedes effects.
- Code-mode uses `pi-durable/codemode` (`createCodemodeExtension`/`createCodemodeTool`): discovery, owned nested tool tasks, journals and deterministic script replay are native.
- Guidance lives in the bundled skill `apps/orb-runtime/skills/codemode/SKILL.md` (syntax, globals, discovery, state/replay, output, images, charts, **all agent-facing limits**). The system prompt says only `Use codemode to compose tool calls.`; the tool description is a two-line bootstrap that reads the skill with `text(await tools.read({path:"/opt/pi-orb/skills/codemode/SKILL.md"}));`. The native budgeted callable catalogue stays inline under section key `tool-catalogue`, with selected declarations, descriptions and namespace headings. The skill requires reading `describeNamespace(name)` (including dynamic MCP server instructions) before first use of a namespace. No automatic skill loading, extra reader tool or execution guard. One complete skill read must fit the reader's 50 KiB/2,000-line limit and the default output budget; a test executes the literal bootstrap through real callbacks against the snapshot.
- Limit constants: `apps/control-plane/src/adapters/durable/tools/callback-limits.js` (callbacks/output) and the skill (heap, store, read, artifacts). Native declaration caps apply, including `unknown` when descriptions make schemas too large; namespace matching is canonical without suffix aliases.
- **Replay and recovery.** Recorded seed, clock, start data and host-ordered deliveries reconstruct a script, not a VM snapshot. Version/fingerprint mismatch, expired deadline or divergent calls refuse **new** nested admissions. Already-admitted replay-safe pending children may still retry; they recheck current authorization/environment but not admission-time preparation or `beforeTool` hooks, and parent cleanup aborts them. Completed callback receipts are reused; external effects are not physically exactly once. The five-minute default deadline is normalized before native `persistStart`, so restart cannot extend it.
- **Store.** Native `store`/`load` state commits only on success, rewinds with history and forks as of the selected entry. Values from the removed `orb.codemode-store` do not carry over and are not deleted (question 81).
- **Results.** Known text tools declare strings; `read` declares string or an image-block array; generic mixed callbacks declare string or a text/image-block array. Deferred MCP tools keep discoverable full raw schemas/results, including arbitrary JSON `structuredContent`, without inlining them. Native formatting: completion/time header, numbered text items, joined adjacent text, final console block; not a JSON envelope. Text spills go to scoped private PostgreSQL artifacts (16 MiB each) whose path is in the completion result; images stay inline; binary saves are declined, with no guest/local temp-file fallback. Bash failures keep bounded output and safe exit/timeout diagnostics; arbitrary exception text stays hidden.
- **Presentation.** Committed `LiveDoc.nestedTools` slots keep nested progress private. The public live view folds only the execution-wait boolean through private `parentTaskId` links. Final nested summaries whitelist ID/name/status/duration/explicit argument keys; raw arguments and private errors stay private. Nested summaries belong to their parent result, never standalone tool rows (`docs/history.md`).
- **`orb_*` results.** All `orb_*` tools and `notify_parent` return native structured objects: per-tool success schemas, `{error: {code, message}}` failures with `isError`. Alert successes include `recordId` and the native `duplicate` receipt. Agent-facing orb tools call application services; the `pi-orb` CLI stays available in execution hosts for shell scripts and boot hooks, and its authenticated local alert endpoint forwards into the central native alert writer without model input.
- **Read images.** Native `createReadTool({ images })` uses the public `ImageProcessor` hook to return original PNG/JPEG/GIF/WebP bytes up to 20 MiB raw regardless of dimensions; it never decodes, resizes or transcodes. Native provider resize defaults would narrow the read contract, so they are bypassed without changing model configuration. Unsupported formats and oversize files return `undefined` for native `unsupported_image`. Scoped resources and private artifacts are checked before delegation.
- **MCP.** Canonical `mcp__server__tool` names; raw-schema validation, background discovery, `mcp_status` and alerts: `docs/mcp.md`. After discovery, root/child extensions are reinstalled through registry upsert and child whitelists updated through `Conversation.configure`. Native tool-phase `api.agent` is cached, so the adapter delegates it to the live `Harness.conversation` resolver; existing roots and children recover tools without recreation. Discovery/refresh failure returns sanitized output without running the script.
- **Charts.** Scripts call `await chart(spec)` (spec: `apps/orb-runtime/skills/charts/SKILL.md`; a test keeps its limits equal to the protocol constants). `parseChartSpec` normalizes and validates (times to epoch ms, null points dropped, ≤6 series, ≤5,000 points, ≤40 bars, unique series names, http(s) `source`) and rejects into the script; at most 8 charts per script, counted against callback caps. Successful chart journal entries derive `LiveDoc` charts in their native commit; `details.charts` commits with completion, never reaches the model, and survives reopen, error and cancellation. Rendering: `docs/web-ui.md`.
- **Isolation.** Scripts get no filesystem, network, process or `require` capability; every effect goes through an injected, orb-scoped callback. The worker thread is not a security principal: callbacks run with host permissions, so they never expose control-plane administrator capabilities, and the QuickJS heap limit is not a process quota.
- Code-mode has no per-conversation, per-orb or process-wide invocation cap; each invocation is a worker with its own QuickJS heap limit, which bounds neither worker nor process RSS. Close/abort stops admission; worker, CPU and memory ownership drain through actual worker exit: the Worker stays referenced until physical termination (`docs/postmortems/2026-10-16-codemode-worker-exit-liveness.md`). Failed or overflowed scripts commit no sandbox state; earlier effects stay.

### CPU budget

On the two-vCPU control plane, all code-mode workers together may use one core; more workers must not multiply that allowance, and admission limits alone cannot contain one spinning script. All central code-mode executions therefore share one process-wide atomic CPU credit pool. Credit refills at one CPU microsecond per elapsed wall microsecond (actual monotonic time, not tick count), capped at 20 ms unused. Overshoot stays as debt across cancellation and reentry; starting another worker never grants new budget. A 20 ms main-thread timer runs only while executions are active and wakes parked workers.

The bounded worker charges its cumulative thread CPU from startup, then deltas at QuickJS interrupts, callback replies and outgoing messages. Exhaustion parks only that worker with `Atomics.wait`, returning normally from the interrupt so VM stack, promises and store survive. Waits are at most 20 ms with cancellation checks between them; the sandbox host deadline/abort/close terminates workers, parked or not. The wall deadline includes budget waiting.

This is cooperative accounting, not a kernel quota: native operations between checkpoints can burst, abrupt termination can leave an uncharged tail, and main-thread callbacks/serialization, WASM compilation and runtime threads are outside the pool. Cloud Run's two-vCPU allocation supplies serving headroom; nothing guarantees ingress never returns 429 (`docs/postmortems/2026-10-09-control-plane-cpu-429.md`).

Each terminal result durably keeps `details.cpu` (`budgetCores`, `cpuMs`, `throttledMs`, `checkpoints`); forced termination can omit the last interval. Result text reports budget waits ≥100 ms. Rollout monitoring uses revision-scoped Run CPU metrics and treats ingress 429s as regressions. Checkpoint and worker-data hooks are sealed in `patches/pi-codemode.PROVENANCE.md`.

### Memory observability

Cloud Profiler cannot see worker threads (`docs/deployment.md`), so workers report their own memory. Profiling the main isolate with `@google-cloud/profiler` is deferred: it adds audit advisories and forcing fixed transitive versions breaks its install.

- **Per worker.** At every CPU checkpoint and on completion (before disposal), the worker writes `used_heap_size + external_memory + owned QuickJS wasm capacity` and the running peak to a shared buffer. Node 26 omits exported wasm capacity from host counters, so the sealed SDK publishes a per-VM getter (current buffer; zero after disposal). Contract tests reject engines that start counting those bytes, preventing double counting. Rejected: host-side `worker.getHeapStatistics()` (the sandbox does not expose its `Worker`). Regression: `apps/control-plane/src/adapters/durable/tools/wasm-memory.test.ts`.
- **Per invocation.** Terminal results keep `details.memory.peakBytes`. A resource failure emits one `lifecycle: orb=<id> codemode.resource_failed kind=<out_of_memory|output_limit|callback_limit|sandbox_exit> peak_mib=<n> conversation=<id> call=<id>`. Timeouts and aborts are not resource failures.
- **Per process.** `tools/codemode-memory.ts` writes one stdout JSON line every 10 s while any worker is live, and nothing when idle:

```json
{"message":"codemode.memory","workers":4,"worker_sum_mib":377.7,"worker_max_mib":210.9,"worker_max_orb":"<orb id>","rss_mib":511.7,"heap_used_mib":17,"heap_total_mib":34.2,"external_mib":8.5,"array_buffers_mib":0.1}
```

This is a deliberate level, not an edge: an OOM kill is a SIGKILL without warning, and threshold edges would miss growth between crossings. Node writes stdout pipes synchronously on Linux, so the last sample before a kill (≤10 s old) survives.

Query: `resource.type="cloud_run_revision" resource.labels.service_name="pi-orb-issuer" jsonPayload.message="codemode.memory"`; add `timestamp<="<kill time>"` for the last sample before a kill (kills appear as `"Memory limit"` platform entries). Resource failures: `textPayload:"codemode.resource_failed"`. Log-based metric for live workers (`gcloud logging metrics create codemode_live_workers --config-from-file=metric.yaml`; use `worker_sum_mib` for memory):

```yaml
filter: resource.type="cloud_run_revision" AND resource.labels.service_name="pi-orb-issuer" AND jsonPayload.message="codemode.memory"
valueExtractor: EXTRACT(jsonPayload.workers)
metricDescriptor: {metricKind: DELTA, valueType: DISTRIBUTION, unit: "1"}
bucketOptions: {linearBuckets: {numFiniteBuckets: 32, width: 1, offset: 0}}
```

## Subagents

Durable owns child conversations. Only the root has the child tools:

- `subagent({prompt, description?, model?})` → `agent_id`. `model` is `Astra`, `Sol`, `Terra` or `Luna` (`SELECTABLE_CODEX_MODELS`); omitted inherits the parent's model. An unavailable model returns `Model unavailable: <name>` before any child exists. Receipts, `get_subagent_result` and `list_subagents` report the selected name.
- `steer_subagent({agent_id, message})`; steering a terminal child returns an explicit error.
- `get_subagent_result({agent_id, wait?})`, `list_subagents({})`, `cancel_subagent({agent_id})`. Cancel commits cancellation control, calls the bound public Harness abort, then waits for owned drain.

Children inherit the pinned parent context, ordinary configuration and authorized tools; no profiles. They share the checkout and may edit it. Results distinguish `completed`, `failed` (with durable detail) and `aborted`.

**No nested children or orbs.** Children select `orb.child-tools`: the root catalog without the subagent tools, `orb_spawn` and `orb_alert`, so those are neither described, discoverable nor callable. The root never selects it and lacks `notify_parent`. A child persists an explicit callable whitelist and the same codemode-only model offering. Rationale: children that inherited spawning described it as available and spawned grandchildren; one given only `orb_spawn` called it "creating subagents". The `subagent` description tells the root children cannot start subagents or orbs.

**Child prompt suffix** (appended to the inherited `orb-instructions` section):

```text
- You are a subagent. Your parent started you in this same orb; you share its filesystem.
- To communicate with your parent agent you have `notify_parent`. Do not use `orb_send` for that!!!
- Do not start subagents or orbs!
```

**Parent notification.** `notify_parent({message})` is described, discoverable and callable only by children; `orb_alert` only by roots, and execution guards reject the wrong conversation before effects. It steers the parent with trusted JSON `{agent_id, description, message}` (`whenBusy: "steer"`), deduplicated by `requestId: subagent-notify:<taskId>:<callId>`; identity comes from trusted child ownership and receipt lookup. `{accepted:true}` means durable native submission, not comprehension. The parent receives it while working, including while waiting for any child; there is no child cancellation, and code-mode propagation is out of scope. Admission is rechecked after async admission and again under the native transaction's orb lock (`projectNotificationAdmission`, `adapters/durable/notifications.ts`); owned drain cannot admit notifications. Only the placed entry projects, identified by reserved `submission.entry` provenance (never JSON-looking text), as a displayed `pi.custom_message` / `subagent-notification` record with `subagent: {kind: "notification", id, description, message}`: no user-role attribution, `inboxMessageIds`, `record.alert`, raw native payload, early submission event, queue or ack cursor. Public history keeps the full plain message for replay, Stop/Start and archives. Rendering: `docs/web-ui.md`. Rejected: escalating to a public alert (flags the user needlessly), tool-output-only delivery (misses idle parents), a separate queue (duplicates native submission authority). `orb_send` instead addresses an agent in another orb (`docs/inbox.md`).

**Waits yield to parent input.** `get_subagent_result({wait:true})` returns on any pending parent steer: human input, another child's notification or a peer orb message, whether already pending or arriving during the wait. The parent inbox uses atomic snapshot-and-watch registration (no lost wakeups). A pending steer triggers a child reread: a terminal child returns its receipt; otherwise the result has `status: "running"` and `interrupted: "parent_input"`. The wait neither consumes the input nor cancels the child. Inside code-mode the interruption returns to the script, which must finish before parent inference resumes.

**Activity and cancellation.** Silent child-only work stays busy through owned cleanup and result handoff; a root result alone cannot grant idle. Children count toward aggregate busy and whole-operation cancellation; operation/child identity fences obsolete observations, and cancellation stays active until owned execution drains. Explicit Abort terminally cancels admitted root/child work; `Harness.close()` (Stop) suspends unfinished tasks for recovery and fabricates no terminal or assistant-abort records. The active roster is display data, not drain authority: reconnect starts unknown until a fresh snapshot, and historical receipts cannot restore live activity. Independent background children do not fail root health.

**Headers.** Child task headers and their `orb.subagent-task` source: `docs/activity-headlines.md`. Root receipts are public; private child transcripts have no viewer or replication.

## Input, outcomes and recovery

- **Input identity:** `docs/inbox.md` ("Exactly-once logical delivery").
- **Operation identity.** An idle native input uses its committed submission ID for the accepted receipt, `operation_started`, patches and `operation_finished`. Allocation reads run inputs and inbox from one committed conversation-view revision; a genuine no-input run or background task uses its task ID. Receipt/history projection alone never allocates an operation. Busy steering and batched/continuing generations keep the aggregate operation until all owned work and public history settle; the next idle input gets a new identity that historical operation/inbox Abort cannot cancel. Native commit publications precede asynchronous replica delivery, so replicas read inside a publication callback are not a coherent checkpoint. A projection-only busy state never invents an operation identity.
- **Output retirement.** Pi's `message_end` and its persisted entry share one message object (pinned by an SDK contract test). The adapter captures that message sequence's live block IDs before Pi appends, associates them by object identity in a weak map and consumes the association once mapping/publication succeeds; a mapping failure leaves live output intact. The canonical mapper emits zero or one block per source block without reordering; when source and canonical counts differ, `detailAliases` are omitted. Frame contract: `docs/runtime-protocol.md`.
- **Aggregate activity.** One operation ID and busy status span root turns, child execution/cleanup and result-wake handoff. Aggregate busy is not root readiness: input during a child-only interval triggers a root turn inside the existing operation; input during whole-operation cancellation waits for the next operation. Completion history and child outcomes precede `operation_finished`; Luna runs only after aggregate settlement. Pi roster rows are always subagents (no `kind: "shell"`).
- **Admission.** New inputs check Sleep and browser-behind-inbox policy through the read-only lease boundary before native submission. Public request-identity lookup comes first; only known Sleep/held-inbox refusals recheck identity, returning typed caller-visible errors without failing the harness. Preflight database/ownership faults and fatal identity-read failures seal admission, fail health, publish the storage-failure edge/error once and join Storage and owner cleanup. The atomic commit guard stays authoritative: a race after a successful preflight fails the Session and requires close/reopen.
- **Peer input.** Provenance, the model-only source label and peer limits: `docs/inbox.md`.
- **Recovery.** `open` alone does not dispatch; `resume`, a submission or a wait starts scheduling. Recovered live tasks add a passive `pi-orb.harness-restarted` notice with safe task identities: visible in history, excluded from model input, triggering no inference and not claiming guest processes died. Restart-limit exhaustion terminally fails the interrupted task. Interrupted model requests consume the native retry budget and backoff. Replay refusal, current authorization, owner fencing and unsafe-effect restrictions hold; unsafe interrupted effects are never replayed automatically. Reopen preserves checkpoints, completed receipts and replay restrictions.
- **Outcomes.** A native failure matching the ending run decides its failed outcome even when recovered partial output is marked aborted. A retained earlier failure cannot mark a later successful queued continuation failed or suppress its summary; human Abort and reset keep their own outcomes. Failures stay user-visible through `server.error` and the durable `harness.reported_failure` edge with safe task/reason/count facts; exception contents stay private. `DurableAgent.open` sets native `afterFailedRun: "continue"` with `steeringMode`/`followUpMode: "all"` for both `model_error` (including declined overflow compaction) and `no_model`: a failed input settles once, without replaying the failed run, before queued input starts; a still-missing model settles the finite queued batch unanswered.
- **Stop/Start.** Ordinary Stop/Start, including host-spec replacement, preserves conversation and authority without a transcript notice or synthetic input; it adopts fresh managed context (`docs/agent-context.md`) and keeps model/thinking settings. Scheduled sleep wakes with one combined restart/sleep-finished model context and one `pi-orb.sleep-wake` event (`docs/lifecycle.md`).
- **Compaction.** Automatic compaction runs inside Durable generation; it is not a settings surface. Manual compaction returns typed `unsupported` without allocating an operation, changing history or invoking a model.
- **Codex failure context.** The sealed Pi AI patch appends sanitized `codex_failure` facts on WebSocket and SSE errors only. Provider `stream`/`streamSimple` wrappers attribute `brokerGeneration` (when known) and `tokenExpiresAt` to the effective `options.apiKey` through an in-memory map of at most 32 bearers; conflicting metadata for one bearer is omitted, unknown request-key overrides get none, and before a 33rd bearer the map clears and attribution stays off until Models is recreated, so delayed requests are never misattributed (`apps/control-plane/src/adapters/durable/models.ts`). Stream errors keep finite SDK retry and a visible terminal failure; tools and partial streams are never replayed and error text never triggers re-login (`docs/postmortems/2026-09-26-provider-auth-failures.md`). WebSocket close errors keep the numeric code but drop the server-controlled reason. A failed `openai-codex` assistant `MessageRecord` with nonblank `errorMessage` may carry `failure.context`, a closed typed object projected from the last `codex_failure` and replicated through ordinary history; absent or invalid facts are omitted. Fields: `brokerGeneration` (nonnegative safe integer), `tokenExpiresAt` (epoch ms, integer 0–8,640,000,000,000,000), `transport` (`sse` | `websocket`), `phase` (`before_message_stream_start` | `after_message_stream_start`), `attempt` (1–20), HTTP `status` (100–599), `wsCloseCode` (1000–4999), `code` (only `invalid_api_key`, `invalid_grant`, `unauthorized`, `authentication_error`, `invalid_token`, `rate_limit_exceeded`, `usage_limit_reached`, `insufficient_quota`, `websocket_connection_limit_reached`, `previous_response_not_found`), `requestId` (`req_` + 8–64 ASCII alphanumerics, or canonical lowercase UUID). `status`, `code` and `requestId` come only from structured data; raw provider text, headers, tokens, fingerprints and WebSocket reasons never appear. Preexisting native diagnostics stay lossless; new Codex facts in native overflow are allowlisted, including an earlier WebSocket fallback leg. `errorMessage` and SDK retry behavior are unchanged; no new frame or UI suffix.
- **Luna summaries.** Owner-scoped Luna uses the same Models and transport override as inference. Its bounded input excludes instructions, reasoning, raw tool output and child transcripts. Completion/idle publication precedes summary inference; failure never changes root outcome or health. VM idle-stop leaves the Harness and summaries running; pending summaries never demand a VM. Graceful sleep/archive wait for pending summaries and their telemetry before closing owner resources; explicit Stop aborts and drains them. The queue is process-local and best effort: a control-plane crash can lose notifications, and reopening never reruns inference to regenerate one. Edges: `harness.summary_queued`, `harness.summary_completed`, `harness.summary_failed` (sanitized, no content).
- Durable root facts and lifecycle edges keep admission, terminal outcomes, cancellation and recovery disposition without exposing child prompts or transcripts. Healthy polling logs nothing.
