# Personal instructions

**Requirement (2026-09-14):** configure one per-user `AGENTS.md` across projects, the equivalent of home-directory agent instructions. The user requested five creative configuration designs in the existing product style before selecting an implementation.

**Status (updated 2026-09-16): Home gear, the user-keyed store and owner-aware runtime read are implemented and qualified.** Stage 2 is not deployed. Question 63 records the UI resolution; `docs/multi-user.md` owns the multi-user boundary.

## Selected implementation contract

- Dashboard totals-strip gear, outside project columns, opens the single-purpose 560px `~/AGENTS.md` editor. Raw Markdown, explicit Save, an icon-only close control, no settings tabs. Phone editing uses 16px text and touch-sized controls. Keep this first slice dashboard-only; the orb-index entry was an optional exploration, not a second required surface.
- PostgreSQL keys snapshots by `user_id`. A valid user without a row reads implicit `{content: "", revision: 0}` until first write; users' revisions advance independently. Each successful explicit PUT atomically replaces only that user's content and increments only that revision. Last-applied-wins, no stale-tab CAS, autosave, blind request replay, revision history UI or new reconciler. A lost acknowledgement may have committed; failures retain the draft and a later Save is a new explicit assignment. Revision overflow fails rather than wraps.
- `GET /api/v1/personal-instructions` and `PUT /api/v1/personal-instructions` (`{content}`) return the signed-in user's snapshot with `Cache-Control: no-store`. Ops must supply `X-Pi-Orb-User-Id` for a known user; a user principal cannot override itself with that header. Readable non-secret Markdown, max 64 KiB UTF-8; empty and whitespace content are preserved, NUL and unpaired UTF-16 surrogates rejected. There is no per-project query or browser-owned user selector.
- A GET-only `/runtime/v1/personal-instructions` uses the active-incarnation bearer to derive `orb → project → owner` and returns that owner's snapshot. The viewer is irrelevant. It is read after the existing secret boot fetch has passed bootstrap authentication, before session/resource initialization. One bounded HTTP request; no new retries or live fan-out. Failure holds readiness with a specific personal-instructions error via existing durable lifecycle/failure reporting. Never silently use empty or a cached old value after a failed read.
- Pi's public `agentsFilesOverride` prepends a virtual `pi-orb:personal/AGENTS.md` context source to native discovery. SDK docs explicitly support virtual context files; no guest/repository file is rewritten. Native agent-dir, ancestor and repository instructions remain in their native order after personal content. `~/AGENTS.md` is the UI's scope label, not an on-disk editing promise. Normal instruction specificity applies, not an invented priority mechanism. The boot snapshot is captured by value so a resource reload cannot fetch newer personal instructions mid-session.
- Fresh and resumed Pi coding sessions adopt on their next runtime start. Separate Luna naming/summary prompts are unchanged. Saving never wakes/restarts compute or interrupts inference. Empty content removes only the managed context source at that boundary. Existing guest-local AGENTS files remain independent and unchanged.
- Before readiness, persist an edge-only, non-model-context `pi-orb:personal-instructions` custom history entry with applied revision and SHA-256. Skip an initial empty revision 0 and unchanged restarts. Persist clearing too. Native session flush/fsync and ordinary replication own durability. No instruction bodies in lifecycle logs or adoption records, no new user-facing healthy-state history row. Startup/adoption failures remain visible through existing orb errors.
- Editor reads once per opening for the signed-in user; an initial read failure shows an error/Retry, not an empty editable file. While Save is pending, disable editing/closing and keep focus within the dialog; show success only after server acknowledgement, once, with `Saved · next orb start`. Error preserves content. Backdrop clicks do not dismiss. Escape/close return focus to the gear. Retain drafts in component memory across close/reopen on this dashboard, never browser storage; leaving the dashboard/reload discards unsaved drafts. No background refresh can replace an unsaved draft.
- Persist owner identity on projects and user keys on instruction rows so wrong-owner behavior is queryable. Typed errors remain visible; logs and adoption records include identifiers/revisions/hashes where needed, never instruction bodies or identity assertions.

### Test-first sequence

1. Protocol validation, real SQL store contracts, and DST over the production read/save service with simulation-backed atomic storage. Race writers and boot readers, inject pre/post-commit failures, assert coherent snapshots/monotonic revisions/no torn text/no false success and stable boot snapshots.
2. Real SDK context contract for personal + native context, empty removal and boot-snapshot stability; HTTP failure/auth boundaries and durable adoption metadata/edge behavior.
3. Browser tests before editor implementation: real gear placement, delayed load, failed load/save, explicit acceptance, focus/dismissal, empty saves, retained drafts, desktop/phone layout and persistence across reload. Full browser/control-plane/runtime E2E checks the actual inference request before/after Stop/Start and compute replacement; authenticated runtime-route tests verify the same saved snapshot is available across projects.


## Five configuration proposals (2026-09-14)

The interactive study is [`design-prototypes/user-agents.html`](../design-prototypes/user-agents.html). It embeds a snapshot of the actual product stylesheet, utility SVG paths and Instrument tile assets. It uses Signal / Boards: white ground, 13px/20px monospace, black one-pixel rules, square controls, inversion, existing 316px dashboard columns and 236px orb index. Study navigation, explanations and failure simulation live outside the product frame. No new brand bar, orientation text, templates, Markdown toolbar or decorative settings cards.

1. **Home gear — recommended smallest first slice.** A right-aligned gear in the existing dashboard totals strip opens a single-purpose 560px editor. The gear belongs outside all project columns; the file title is `~/AGENTS.md`. This reuses familiar Config geometry without making personal instructions a project tab. Tradeoff: a second gear scope and limited room for a long file. In a production orb view, the equivalent entry could occupy the index home row rather than every project header.
2. **Footer folio.** A quiet `~/AGENTS.md` link in the existing system footer navigates to a full-page raw-Markdown document with a dashboard return. The editor has abundant vertical room and a stable Save footer, without inventing a general account-settings hub. Tradeoff: the entry is less prominent and editing takes the user away from the fleet. A production destination should be link-native/addressable, not merely a component toggle.
3. **Personal fold.** A single disclosure between the totals strip and the project grid unfolds a writing band. At desktop width the 236px filename cell sits beside the editor; on a phone the filename sits above it. Scope becomes spatial: personal instructions live above all projects rather than inside one. Tradeoff: one permanent dashboard row and less visible fleet height while editing. It does not create a fake project or affect project counts/order.
4. **Scope switch.** An existing project gear opens Config with a `Me / pi-orb` scope switch. `Me` contains the personal file; project scope keeps General/MCPs/Secrets. This adds no global entry point and works wherever project config already exists. Tradeoff: highest scope-confusion risk; the document is personal, never a per-project copy or override. A production implementation must preserve drafts separately when switching scopes.
5. **Margin sheet.** A compact `~/` control in the orb index home row opens a right-anchored, 480px writing sheet over the transcript. On phones it is reached from the orb header and occupies the conversation width. The message draft stays separate. This places editing at the moment a repeated agent preference becomes apparent, borrowing the existing terminal shade's independent-workspace idea. Tradeoff: transcript occlusion and another occasional orb utility. No global instruction command is added to the composer; its decided model/thinking-only command vocabulary is unchanged.

**Home gear was selected by the user (2026-09-14).** The other four remain rejected alternatives for this slice. Personal fold is the most distinctive scope treatment; Footer folio is strongest for long documents. The five are alternatives, not five entry points to ship together.

## Initial shared behavior proposal (superseded by the selected contract)

- One readable, editable Markdown document owned by the user/account, shared across projects; not a secret and not browser-local authority.
- `~/AGENTS.md` communicates home-directory scope in this study; it is not a claim that a particular guest path or SDK loading mechanism has been implemented or selected.
- Personal content stays separate from repository-owned `AGENTS.md`; never rewrite or commit project instructions as a side effect of a personal save. The native instruction layering and exact loading path require qualification before implementation; do not claim a new precedence rule from these layouts.
- Explicit Save, with an unsaved indication only when needed. Empty content is a valid way to remove personal instructions. No automatic prompt submission or agent-generated rewriting.
- Recommend adopting the saved document at the next orb start, including restarted existing orbs. A save must not wake stopped orbs, restart active ones, or interrupt a turn. This is a proposal, not a settled requirement. The save receipt states the adoption boundary once rather than displaying repeated help text.
- Failures remain beside Save and retain the draft. Closing/reopening in the study preserves an in-memory draft; a page reload discards all simulated state. A failed fetch in the real editor must be visibly unavailable, never presented as a successfully loaded empty file.
- A production save receipt must follow authoritative persistence, not an optimistic textarea update. Later runtime adoption must be distinguishable from configuration save. Record the applied content identity and adoption failures durably in existing runtime/history/lifecycle facilities, without logging instruction bodies. User-affecting adoption failures must be visible, not just guest stdout. The exact delivery design and invariant tests belong to the selected implementation plan, not a speculative reconciler in this study.

## Prototype boundary and checks

All content and mutation outcomes are simulated in browser memory. Project/lifecycle controls are disabled visual references, except the Scope switch proposal's entry gear. The footer host/version and project/orb data are illustrative. No real fetch/save, runtime delivery, model invocation, autonomous machinery or telemetry is introduced. Editing from the study never changes this repository's or any orb's instructions.

`design-prototypes/user-agents.smoke.mjs` exercises all five actual entry points and selectors at desktop and phone width, editing, explicit saves, injected save failure and draft retention, close/reopen, scope switching, message-draft independence, horizontal containment and script errors. Screenshots are diagnostic artifacts in `/tmp`, not committed design assets. All five passed at 1440px and 390px (2026-09-14), including a separately edited message draft and the fold's hover contrast. Visual inspection found a cascade collision between the fold's gray background and the shared white hover text; an explicit black/white hover pair fixes it and the smoke check pins both computed colors. These checks qualify the static study only, not native keyboard behavior, production accessibility or runtime adoption. These prototype checks are distinct from the production qualification below.

## Production qualification (2026-09-14)

Tests were written and run before their production implementation. The red baseline failed on the missing protocol/store services, missing personal SDK context source and missing dashboard gear; the expected baseline logs were preserved under `/tmp/personal-instructions-*-red.log`. The editor test subsequently exposed a deterministic scenario mistake: it tried to save empty content a second time after empty was already the saved value. The corrected scenario explicitly asserts disabled Save for unchanged content, verifies clearing across reload, and tests draft retention independently.

Final local validation:

- `npm run typecheck` and `npm run lint` pass (one pre-existing lint warning and one pre-existing info).
- `npm test`: 1,690 unit/DST/contract tests passed, five existing skips, plus all infrastructure suites. The focused personal suite includes 160 recorded DST schedules with concurrent writers/readers and pre/post-commit failures; real PGlite migration/atomic-assignment/revision-exhaustion contracts; cross-project runtime bearer/read-only authority; bounded HTTP failure handling; SDK native-context preservation and immutable reload behavior; and silent/changed/cleared adoption metadata.
- `PI_ORB_E2E_BACKEND=process npm run test:e2e`: **53 passed, two explicit platform skips**, final complete rerun exit 0. Both Chromium and WebKit run the personal editor test at desktop and 320/390/600px widths, with load/save barriers, failure preservation, focus, dismissal, explicit acceptance and persisted clearing. The full runtime slice proves actual model-request content remains unchanged after a live save, changes on Stop/Start, and is absent after clearing plus compute replacement; adopted identity is replicated without instruction bodies.
- The first complete E2E run found an existing terminal test's cumulative pre-ready connection-count race. A cause-based, test-only emulator/socket ownership checkpoint fixed it; no production terminal code or timeout changed. The final whole suite passed with source held unchanged. Evidence and rationale: `docs/postmortems/2026-09-14-terminal-retry-pre-ready.md`.
- The shared frontend-only service was inspected in Chromium at desktop and phone sizes. It uses simulated storage and is not production deployment. Docker's daemon is not active in this environment; the two process-mode skips are the Docker interrupted-turn scenario and network PostgreSQL driver contract, not personal-instructions tests.

The original run logs were `/tmp/personal-final-unit-all.log`, `/tmp/personal-final-types.log`, `/tmp/personal-final-qualified-lint.log`, and `/tmp/personal-e2e-qualified.log`. These temporary logs did not survive the subsequent compute restarts; the first-failure excerpt and diagnosis remain in `docs/postmortems/2026-09-14-terminal-retry-pre-ready.md`.
