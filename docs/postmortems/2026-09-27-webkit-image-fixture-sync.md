Release [36301922542](https://github.com/schani/pi-orb/actions/runs/36301922542) on `5dcb4159df0663318c7b89f957618b43f542e62b` passed Docker full-slice 4/4 but failed one of 227 E2E cases: WebKit could not find `image failed to load` under `broken_source`. The separate [main E2E run 36301912890](https://github.com/schani/pi-orb/actions/runs/36301912890) failed the same case; an independent diagnostic-branch E2E passed, which did not clear either failure. Both failed-run logs retain the first assertions. The [release artifact](https://github.com/schani/pi-orb/actions/runs/36301922542/artifacts/10926696000) records `failed-before-apply`, `applyAttempted=false`; serving did not change.

The image test fabricated three extra records only in intercepted HTTP history, including a `broken_source` image URL returning 404. It left the orb running. Its real WebSocket sync does not know that fabricated head: `sync.started` in `full` mode clears the browser's records and replaces them with the runtime's unmodified history. The test observed `missing_source` before awaiting the asynchronous broken-image error; which happened first—WebKit's image error or full sync—determined its outcome. The CI failure logged no full DOM/transport trace, so this is a controlled sufficient reproduction, not a claimed capture of its exact network schedule.

A test now holds the broken-image 404 across a clock-driven metadata poll, awaiting its named response and the applied orb header before releasing the image. With the running fixture, both browsers deterministically lose **both** synthetic image rows despite two intercepted history responses carrying all 24 records and head `fixture-broken-source-result`; the browser trace records `sync.started {mode:"full"}`. The baseline fails on the unchanged `missing_source` assertion, before the held response is released. The corrected fixture serves this HTTP-only orb as stopped, verifies no live socket opened, preserves both rows after that applied poll, then releases and observes the exact 404 and failed-to-load UI. The same gated test passes in Chromium and WebKit, as do all 16 image E2Es. No timeout or image/product behavior changed. The corrected full Docker-backed [release 36306373668](https://github.com/schani/pi-orb/actions/runs/36306373668) passed and was validated.
