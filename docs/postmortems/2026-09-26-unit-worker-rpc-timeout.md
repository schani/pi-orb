# Unit worker RPC timeout during diagnostic qualification (2026-09-26)

The clean `npm ci` applied all three diagnostic patches. Typecheck and lint passed (three pre-existing warnings, one informational diagnostic). Full process E2E with isolated network PostgreSQL passed 218 tests in 24 files, with one Docker-only skip (one file skipped). Standalone infrastructure passed 110 tests: 36 Node, 50 Python, 24 native VM. The unit run reported 2,250 passed and eight skipped, with no failed assertions, but **`npm test` exited 1**: Vitest reported an unhandled `[vitest-worker]: Timeout calling "onTaskUpdate"` (`/tmp/diagnostics-qualified-unit.log`, lines 552–571). It did not name a task or file. No new DST trace was generated.

The unit run ran 03:56:20–04:09:46 UTC, overlapping E2E 03:55:19–04:24:58 on a two-CPU host; `maxWorkers: 50%` permits one unit worker. Vitest's worker `onTaskUpdate` RPC awaits coordinator state and reporter acknowledgement; its 60-second RPC timeout is independent of the 30-second test timeout. Concurrent resource contention is plausible, **not proven**. Aggregate cgroup counters showed no OOM or throttling, but provide no interval evidence. Do not attribute this to the last printed migration test.

The first failure was preserved without a green-seeking rerun or timeout increase. Its unnamed task cannot now be recovered: the old `/tmp` traces were lost after host restart. Concurrent contention was a hypothesis, not an established cause; a later attempted concurrent E2E used the default Docker backend and failed setup because Docker was unavailable. The serialized green run of 2,250 tests did not clear the failed gate.

Subsequent instrumentation recorded 1,039/1,039 worker RPC acknowledgements. The worst took 36.48 s although the coordinator received and replied within 1 ms: the worker event loop was blocked for 35.57 s by synchronous `execFileSync` calls to `ssh-keygen`/`bash` across 50 `packages/native-image/src/host-key-boot.dst.test.ts` iterations. This established the starvation class, not the identity of the original stalled test. Those temporary dependency patches were restored.

Controlled reproduction with pinned Vitest 3.2.7 and four ~15.5-second synchronous child-process gates isolated the mechanism. Vitest starts its 60-second `onTaskUpdate` RPC timer when the worker sends the request. The coordinator replied within ~6 ms while the worker blocked in its first gate. With only resolved-Promise boundaries between gates, the worker did not service the queued IPC reply: the test passed, but its RPC timer fired at 62.079 s and Vitest exited 1. With identical gated work and a host-loop handoff between gates, the worker received the reply at 31.022 s and exited 0. The first fixture attempt gated the wrong RPC and let its child time out at 85 s; it is retained but is not a valid positive control.

The actual `runDst({ iterations: 4 })` under the same gate acknowledged at 31.044522 s and exited 0. The minimal harness fix imports `setImmediate` from `node:timers/promises` and yields between **completed** DST iterations only, outside scenario and error handling. Replay, final iteration, virtual scheduling, and recorded traces are unchanged. A test-first red host-turn ordering regression and replay/failure-artifact/lifecycle assertions pass; 20 focused selected tests pass. This fixes the reproduced worker-starvation class, **not a proven attribution of the historical unnamed task**. The original failed gate remains failed; it was not cleared by a green rerun.

Final sequential qualification on the corrected tree passed: `npm run typecheck`, `npm run lint` (three pre-existing warnings, one info, no failures), and `npm test` (exit 0; 2,251 unit tests passed, eight skipped; 110 infrastructure tests: 36 Node, 50 Python, 24 native VM).
