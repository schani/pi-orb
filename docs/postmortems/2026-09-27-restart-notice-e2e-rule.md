The initial [PR CI failure](https://github.com/schani/pi-orb/actions/runs/36299158267) tested merge `d23c19742503dd1aad123694257ba1923c3bc13c` (parents `2c486a3ba3eefdc0012cdd012762252a06cbe2db` and `592fc8b059994cb4930d8be3bf849fdec479da7b`), not the process-qualified `592fc8b` source. The branch artifacts built at `592fc8b` were retained, not deployed; sandbox generation 2 still runs old `6f6de57`. The failure is deterministic text-contract drift, not a DST trace or evidence to raise timeouts.

The [production release run 36299905272](https://github.com/schani/pi-orb/actions/runs/36299905272) on `d512030d294fb570f25c37d85cd8dacc845a6929` failed during checks, before apply. The allowlisted [release artifact](https://github.com/schani/pi-orb/actions/runs/36299905272/artifacts/10926225660) records `outcome=failed-before-apply`, `applyAttempted=false`; production serving was unchanged. The first CI failure and artifact remain at those URLs.

The full-slice fake model consumed ordered regex rules. Its restart rule matched `^The (host|agent runtime) was restarted\.`. The current settled host-restart notice begins `The host was restarted involuntarily.` (`docs/lifecycle.md`); the rule could not match that prompt, so the scripted reply could not appear. Process-backed E2E passed because its runtime-only notice still begins `The agent runtime was restarted.`. The Docker timeout was a fixture/contract mismatch, not evidence that the composer fix changed restart behavior. The sleep-wake E2E's similar matcher remains correct: its combined sleep notice uses the separate `The host was restarted.` context, not the settled-host notice.

A test now generates both settled notices from `planBootNotification` and checks the exact regex used by the full-slice mock. It failed against the original fixture matcher at the host case and passes after naming the two actual starts explicitly. The test rejects the obsolete generic host sentence and unrelated prompts. No timeout, release gate, product wording, or restart assertion changed. The corrected full Docker-backed [release 36306373668](https://github.com/schani/pi-orb/actions/runs/36306373668) passed and was validated; a green rerun alone would not have established this cause.
