The mock source is in [`glideapps/fake-openai`](https://github.com/glideapps/fake-openai), inspected at `34dc7889ae7cfc48d2db39b7131c13d01b95481c` (2026-07-27); the deployed revision was not independently verified; `packages/mock-openai` only overrides Pi's provider. `src/worker/stream.ts` enqueues each SSE frame then awaits an individual D1 event-log insert. Both a client abort and **any** error in that loop (including an event-log insert error) set `aborted=true` and finalize the request; the catch discards the cause. The isolation rule has no delay before event1. Since each frame is enqueued **before** its insert, a normal event1 insert rejection before commit leaves event0 alone in the durable ledger but can put both event0 and event1 on the wire; failure before event0 commit leaves no durable events. Event0 alone is consistent with either client cancellation after event0 commits or an ordinary event1 insert failure; no lost acknowledgement is required. Neither cause was observed in the original run, which recorded only the mock ledger and the SDK's generic EOF error, not wire event count. Directly aborting the Pi fetch normally produces `AbortError`, while the original client reported clean SSE EOF; cancellation would require an intermediary stream closure that is not evidenced. The event loop can also fail between inserts, though no such operation is evident for this rule. A deterministic test against an isolated temporary copy of the **original** `src/worker/stream.ts` from git revision `34dc7889ae7cfc48d2db39b7131c13d01b95481c` (SHA-256 `665c4df0f073a8e75415cfb377beeb49c89b45a46c8335230c1977a715e93403`) proved the overlooked path: event0 commits, event1 (`response.output_item.added`) insert rejects without commit, two nonterminal SSE frames are enqueued, the durable ledger contains only event0, and finalization receives `aborted=true` (one test passed). The original copied source and temporary test were removed after the run.
