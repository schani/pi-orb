# 2026-08-05 — unreachable-restart livelock against real VM boot times

Status: open — the fix is tracked in `TODO.md`. The lifecycle rules this incident indicts are in `docs/lifecycle.md`. Orb 104600b7 remains `failed` pending the fix.

**Field finding (2026-08-05, orb 104600b7, `drain_runtime_unrecoverable`): the inline unreachable-runtime restart livelocks against real VM boot times.** Reconstructed from GCE operation audit logs and boot-disk journal forensics (the control plane emits no app-level logs — itself a gap). At 21:16:22Z the VM received a hypervisor ACPI power-off while the orb was `running` (no stop API call and no preemption/hostError event was logged; on a Spot VM the only designed-for source of an unlogged ACPI soft-off is preemption, whose terminal operation was evidently masked by our own stop racing it 32 s later). During the ~30 s ACPI soft-off window the instance still observes as `running`, so the *liveness* path won the race against the *observation* path: at 21:16:54 the 30 s `unreachableGraceMs` expired and the reconciler did its inline `stop`+`start`. From there the loop was self-perpetuating: a COS VM needs ~60–70 s from `instances.start` to a serving runtime container (journal: userspace up ~26 s in, Docker initialized ~33 s in, container started ~35 s in — 2 s before each next stop landed), but the restart path grants only the same 30 s grace before concluding unreachable again. 38 stop/start cycles over 38 minutes, each hard-stopping a booting VM (repeatedly exercising the docs/history-replication.md/Q33 durability gap). The `running`-state loop has no deadline and would have cycled indefinitely; it ended only because idle-stop moved the orb to `stopping`, where the drain deadline expired into `drain_runtime_unrecoverable`. The intended "preemption surfaces as TERMINATED → stopped → normal restart path" never engaged because the inline restarts kept re-starting the instance before it could be observed as stopped. Root defects: (a) the post-restart liveness grace is shorter than a real boot, guaranteeing livelock whenever the inline restart fires against a full VM boot; (b) the inline restart stays in `running` instead of re-entering `starting`, so the patient readiness path (5 s health polls, 15-minute deadline) never takes over; (c) DST did not catch it because `FakeWorld` boots hosts instantaneously — boot latency must become a modeled, schedule-controlled delay.
