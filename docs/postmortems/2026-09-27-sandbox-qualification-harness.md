# Sandbox qualification harness failures (2026-09-27)

The isolated PR #51 sandbox exposed several **qualification harness** errors. Preserve the first failures; a passing rerun alone does not qualify a release.

- OCI inspection initially compared the registry index digest with the amd64 child digest. Pin and record both; verify the amd64 child actually selected by Cloud Run. Candidate `0158472` used index `329d7146ea7c5cd4e9e97391c24d1a40818bfac8275ffcb8280e4529f0f81f97`, child `dd5de86a17378f62328c28b2fb455c2954b0f9e810812b50d17df55218e6bb5c`.
- The old-VM retention guard incorrectly assumed the i0 GCE VM should remain after replacement to i1; require the old VM's absence while preserving the disk. Separately, Cloud Run revision deletion cannot prove controller retirement: inventory, positive-then-explicit-zero active **and idle** Monitoring samples, no newer positives and no pending GCE work precede activation. No absence-only zero, extra post-delete retirement requirement or increased timeout substitutes for the shared gate.
- Fixture wrappers in `fixture.py` / `preview.py` passed the wrong gate-input shape before I/O. Contract-check the wrapper before interpreting its failure as deployment evidence. A manual environment selection inherited cached GCP credentials and falsely appeared to prove WIF; a fresh isolated configuration must obtain a new orb JWT, exchange via STS, impersonate the sandbox service account and exercise the intended API. Wrong audience must fail at STS. A Fastify/control-plane POST-start HTTP 400 for an empty JSON body occurs before the intended domain check and proves neither successful domain authorization nor denial.
- A live helper idled out at 900 seconds during asset upload. The partial record derives historical WIF from control flow, **not** a fresh wire replay. Bounded normal presence/connection resumed only missing asset, preview and browser checks, without changing the idle policy. Synchronize on owned fixture state rather than increasing timeouts or retrying to get green.
