## Correction

**Decision, 2026-10-08:** runtime-image package installation separates acquisition from writes. `infra/runtime_apt.sh` performs an authenticated update with `APT::Update::Error-Mode=any`, then at most two `--download-only` acquisitions with `Acquire::Retries=0`. It retains APT's signed-index/expected-package-hash checks and verified cache, then runs exactly one `--no-download` installation. Failed acquisition exits without installation; a failed installation is never repeated. Each download attempt/failure and the install boundary persist in Docker/Actions logs. The existing 40-minute E2E job budget and transport timeouts are unchanged. This bounds attempts, not a promise that every network condition completes within the job budget.

Read-only package GETs are safe to repeat before dpkg; generic whole-install retries are not. No trust bypass, ignored HTTP errors, source refresh on mismatch, mirror fallback or speculative retry options are introduced. A persistent mismatch remains a build failure. Ubuntu runner source selection (`infra/runner_apt.py`, `docs/postmortems/2026-10-07-runner-apt-timeout.md`) operates outside this Debian container and cannot correct its package response.
