Skills and secrets for all projects / five directions

Memory only · no real configuration changes
Shared semantics, identical in all five:
  • Owner-scoped. Every orb of every project the owner has gets them; adopted at the next orb start, like instructions and project secrets.
  • Secrets: write-only env vars, same name rules and limits as project secrets. A project secret with the same name wins in that project; the global row says where it is overridden.
  • Skills: one raw SKILL.md each, explicit Save. Name and description come from the frontmatter (no separate name field); renaming the frontmatter renames the skill. A repository skill with the same name wins.
