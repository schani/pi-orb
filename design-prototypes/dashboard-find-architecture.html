Application navigation · ADR

Find architecture

A reusable client-side search shell that opens with Command-K, accepts route-owned sources, and renders every result as a native link.

✓
Decision

Use a generic app-search shell and pure matching core, the centered Index card presentation, and link-native results. The dashboard is the first source—not a special case in the framework.

01 · contract

Goal and scope

Find searches dashboard resources already loaded in the browser. It is navigation—not a general command palette or transcript search.

⌘KorCtrlK
Project namesDISPLAY NAME
GitHub URLsREPOSITORY URL
Orb namesWORKING + ARCHIVED

IDs, lifecycle state, transcript content, checkout files, and agent output are deliberately excluded. The shortcut exists only on the dashboard; other routes retain browser defaults.

02 · reusable data flow

Generic shell, route-owned sources

The dashboard is the first source, not part of the framework. An application-level provider owns Command-K and the Index card; a React-free core owns matching; each route maps its own state into generic items.

AppSearchProvider is mounted once and intercepts Command-K only while a route has registered a source. app-search.ts has no React, route, transport, project, or orb imports. A route owns any fetching and typed errors, then supplies a synchronous source snapshot; the shell never accumulates resource-specific cache or transport policy.

03 · search semantics

Predictable matching

  1. Trim, Unicode-normalize with NFKC, and apply locale-independent lowercase.
  2. Use contiguous substring matching; fuzzy ranking is intentionally deferred.
  3. Match only explicit source-supplied keywords—never infer searchable fields from rendering.
  4. The dashboard adapter adds raw and normalized GitHub URLs and orb display names; orb result context uses the dashboard's formatted creation age rather than its removed abbreviated hash, without making age searchable.
  5. Preserve source order; the generic core invents no relevance ranking.
  6. Render at most 50 overlay rows while reporting the complete match count.

An empty query shows scope help, never invented “recent” resources. Every item supplies an href and every row is an anchor. Project results use #/projects/:projectId; orb results use #/orbs/:orbId.

04 · selected design

The Index card

A modal card keeps the current route recognizable while providing enough horizontal space for result context.

Rows are native links: click, Command/Ctrl-click, middle-click, keyboard activation, link preview, copy-link, and context menus work normally. Only an unmodified same-tab activation closes the card. The focused project URL loads the ordinary dashboard and focuses that panel; a missing project gets its required resource-specific missing page.

05 · changing truth

Loading, failures, and mutation

The index contains only resources successfully loaded into dashboard state and grows in place as orb-list responses arrive. It never keeps an independent cache.

Searching loaded items · some orbs still loading

A failed orb list remains visible in its project panel and qualifies the zero-result message. Rename, auto-name refresh, archival, and deletion rebuild the derived index. Selection is derived synchronously from one stable active key, so pointer and keyboard can never paint two selections. Remembered pointer coordinates distinguish actual movement from stationary-pointer events caused by a redraw, preventing a transient selection under an unmoving pointer. The result region stays mounted and replaces rows directly, avoiding an intermediate empty-frame flash.

06 · interaction

Keyboard and accessibility

  • One app-level listener handles (metaKey || ctrlKey) + K only when the active route registers a source; there is no persistent header hint.
  • Repeated Command-K focuses and selects the query; Escape closes and restores prior focus.
  • Up/Down and actual pointer movement update the same sole active result; Enter activates it; Tab follows normal controls.
  • The close control and every result arrow share one trailing-column center.
  • The query is a labeled type="search" input in an aria-modal="true" dialog.
  • One polite live region announces result count and partial loading or failure state.
  • Result accessible names include resource kind and parent context; visual marks do not fragment those names.
07 · confidence

Testing and observability

Core + adapter testsGeneric keyword matching and limits stay separate from dashboard URL aliases, scope, order, and mutation.
Provider + dialog testsSource registration/reset, browser default without a source, focus, anchor hrefs, and modified clicks that leave the card open.
End-to-endDistinct project, URL, working-orb, and archived-orb queries navigate correctly.
User-visible diagnosticsMatch count, indexed state, and partial loading/failure—not noisy lifecycle events.
08 · decision history

Rejected presentation alternatives

  • Header lens: compact, but competes with project actions.
  • Margin index: excellent on wide screens, too transformational on phones.
  • Filter folio: preserves row actions, but rearranges and dims the dashboard while typing.
  • Bottom ribbon: familiar, but weak at showing repository and parent context.

The alternatives remain interactive in the five-design study. They share this indexing contract but are not implementation targets.
